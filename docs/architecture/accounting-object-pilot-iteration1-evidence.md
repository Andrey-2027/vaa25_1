## Изменённые общие границы

- RegisterSliceReader читает ссылочный ресурс и исключает выбранного регистратора
  как из кандидатов, так и из сравнения победителей среза.
- Очистка набора получает RecorderSetWriteAuthorizer и проверяет DELETE до flush;
  отказ права на регистр сохраняет документ, строки и набор.
- Подпись регистратора получает projection с id и конечными instance-name путями.
- ItemTable.refreshRows обновляет отображение с сохранением черновиков / dirty.
- Редактор корректировки привязывает загруженные строки к текущей шапке формы,
  устраняя обращение к отсоединённому lazy proxy родителя.

При повторной проверке выявлены старые локальные JAR и неполные API-baseline
у уже объявленных общих границ C5 / агрегатного сохранения / REST и нового
refreshRows. Зависимости пересобраны; baseline синхронизирован с исходниками
и существующими реестрами ролей. У platform-rest-web публичных ролей нет,
поэтому его SEMANTIC_ROLES baseline содержит только шапку. Сравнение нормализует
CRLF в LF; изменения сигнатур продолжают проверяться. Финальные API / architecture
проверки пройдены в общем пакете из 62 проверок.

## Окружение и ограничения

Prepare копирует только public-схему исходной локальной базы; данные не копируются.
Применяются миграции периода цен, часов порядка записи и таблиц пилота.
Run использует validate, создаёт примеры атомарно и слушает 127.0.0.1:18080.
Verify создаёт отдельную базу g3_register_test_accounting_pilot_* с create-drop;
интерактивная и исходная базы не являются целью этих тестов.

База v3 создана для актуального C5 с явными операционными грантами учётки;
предыдущая v2 сохранена. Пароль генерируется локально и хранится в игнорируемом
config/accounting_object_pilot_local_v3.login.local, без публикации в документации.
Профиль отключает REST HTTP-адаптер и использует поддерживаемый resolver
без session-cache для инициализации примеров и чтения UI.

Права на документы и регистр независимы, CHECK_ONLY по виду сущности;
построчные ограничения регистра по цехам не включены. Подбор максимум 200 объектов
цеха с явным отказом при превышении; минимальная табличная часть — одна строка;
дата без часового пояса, до микросекунды; номер ручной и уникальный в виде документа.
Блокировка цеха сериализует все его записи. Отчёты / экспорт / production и
полное закрытие Г0–Г8 остаются за пределами итерации.

## Исправление по пользовательской пробе — 2026-10-07

Открытие новой карточки номенклатуры отказало: её default-конфигурация читает
AttributeType ещё при создании формы, а исходная учётка пилота имела read только
для восьми основных типов. Право операции ENTITY:Nomenclature уже было выдано.

Добавлены read-grants GroupNom, AttributeType, AttributeValue, NomAttributeValue,
NomSklAttribute в инициализатор новых примеров. Для существующей базы v3 применён
ограниченный скрипт accounting-object-pilot-nomenclature-read-grants.sql:
INSERT 0 5, COMMIT. Новые гранты разрешают только чтение; существующие права
и предметные данные сохраняются. Проверки из таблицы выше относятся к пакету
до этого исправления; повторный прогон тестов для этой правки не выполнялся.
