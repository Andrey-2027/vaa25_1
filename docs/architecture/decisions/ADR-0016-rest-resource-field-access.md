# ADR-0016: доступ к полям опубликованного REST-ресурса

- Статус: принято по решению пользователя 2026-10-06
- Область: F-REST-READ, LIST и DETAIL; дополняет ADR-0007 §4.1

Уточнение 2026-10-07: [ADR-0018](ADR-0018-no-field-permissions.md) распространяет
отмену отдельных прав на поля на все каналы. Упоминания ниже о сохранении
attribute API означают только совместимость старых сигнатур; отдельной
проверки ATTR больше нет.

## Решение

Право `REST:<resource>:v<major>:LIST|DETAIL` и C5 entity read дают доступ
ко всем полям соответствующей операции, явно опубликованным прикладным
программистом. Отдельные attribute grants не требуются для вывода, обязательного
`id`, объявленных фильтров, сортировок или tie-breaker.

LIST и DETAIL независимы. Декларация задаёт maximum/default проекции каждой
операции. `fields` выбирает только опубликованные aliases; неизвестные поля,
фильтры и сортировки отклоняются с 400. JPA/UI metadata не расширяет контракт.

Для используемых путей через to-one сохраняются entity read целевой сущности
и проверка её RLS. Ограничения строк корня, CHECK_ONLY целевой сущности и
доказательство эквивалентности FILTERABLE root/target не меняются. Загрузка
fixed fetch superset не требует прав на неиспользуемые ссылки.
Canonical read path, authentication, capability gates и запрет экспорта JPA остаются.

## Причина

Grants на каждый обычный атрибут дублировали разрешение экспортировать явный
REST-контракт и затрудняли создание учётки. Декларация уже задаёт границу данных.
Специальная категория «защищённое поле» в этом срезе не вводится.

## Совместимость

Это изменение авторизации расширяет доступ существующих субъектов с API/entity
правами до всех опубликованных полей операции. Прежние attribute grants больше
не участвуют в REST-проверках и не регистрируются REST registrar; записи в БД
автоматически не удаляются. Общие C5 attribute API и другие каналы не изменяются.

Wire/schema и major v1 сохранены. Решение заменяет требования обязательных
attribute grants в прежних планах этапов 3/4. Исторические evidence остаются
результатами прежней модели; актуальная приёмка фиксируется отдельно.

## Пример

Для `GET /api/v1/nomenclature` достаточно чтения
`REST:nomenclature:v1:LIST` и `ENTITY:org.ip.model.Nomenclature`.
Для карточки требуется независимый `REST:nomenclature:v1:DETAIL` и то же entity
read. Доступны опубликованные поля, фильтры и сортировки разрешённой операции;
применимые ограничения RLS сохраняются.
