# ADR-0018: отдельные права на поля отменены

- Статус: принято по прямому решению пользователя 2026-10-07.
- Область: все каналы приложения, включая редактор запросов и отчёты.
- Решение пользователя: «Никаких проверок полей быть не должно».

## Решение

Авторизация выполняется по сущности, операции и применимым ограничениям строк RLS.
Отдельных прав чтения/записи полей нет. Субъект с правом чтения сущности получает
доступ к её полям в пределах контракта соответствующего канала. ATTR-grants не
требуются для SELECT, условий, соединений, агрегатов, сортировки, id, version и аудита.

ReportReadAuthorizer проверяет ENTITY-read и RLS всех участвующих типов, включая
источники CTE, подзапросов, WHERE/ON и сущности параметров. Проверка всех
persistent-атрибутов удалена. Подготовка модели attribute lineage для авторизации
не требуется. Scalar-проекция, ограничения формы запроса, проверки связей RLS,
запрет произвольного экспорта JPA-сущностей и реальное применение фильтров сохраняются.
Проверки наличия/типа/публикации полей запроса остаются валидацией контракта,
а не отдельными правами пользователя.

REST сохраняет права на опубликованную операцию, entity read, maximum/default
проекции и список допустимых фильтров/сортировок. Право на сущность не расширяет
декларацию REST. Canonical CREATE/UPDATE/DELETE и ACTION также сохраняются.

## Совместимость

Старые методы attributeRead/isAttributeReadPermitted оставлены deprecated для
совместимости. Основной evaluator проверяет через них только ENTITY-read.
Старые ATTR read-ключи нормализуются в ENTITY:<FQN> перед запросом грантов;
чтение, регистрация и решение не создают отдельной field-политики. Новые
write-определения ATTR и редактирование ATTR-grants запрещены как устаревшая
конфигурация. Старые записи ATTR в БД не удаляются и не используются для допуска.

Это решение заменяет требование всех ATTR-grants в ADR-0014 и расширяет отмену
из ADR-0016 на остальные каналы. Прежние evidence и планы описывают старую модель
и не могут служить основанием для повторного включения field enforcement.

## Реализация и проверка

Изменены report gate, compatibility API/владелец C5 read, registry и административная
граница; существующие сценарии приёмки приведены к entity/RLS модели.
Результаты сборки и ограничения проверки: docs/plans/c5-no-field-permissions-evidence.md.
