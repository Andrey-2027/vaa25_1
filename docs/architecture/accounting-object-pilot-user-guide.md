# Объекты учёта — первая пользовательская проба

Режим: **пилот, итерация 1**. Объём и критерии готовности:
[план пилота](information-register-accounting-object-pilot.md).

## Подготовка и запуск

Команды выполняются из корня `GitVaa25`, в PowerShell. Нужны JDK 21,
PostgreSQL 17, установленные локальные зависимости Maven и
`config/application-local.properties` с подключением к локальной базе приложения.
Реквизиты используются без вывода пароля в журнал.

```powershell
# Один раз для новой базы:
./scripts/accounting-object-pilot.ps1 -Mode Prepare
# Каждый запуск:
./scripts/accounting-object-pilot.ps1 -Mode Run
```

Если расположение инструментов отличается, задайте `-Maven` и `-PostgresBin`.
Адрес: `http://127.0.0.1:18080`. Логин: **accounting-pilot**.
Скрипт генерирует пароль и сообщает путь к игнорируемому файлу
`config/accounting_object_pilot_local_v3.login.local`; откройте его локально.
Этот файл нужен при последующих запусках той же базы.

База по умолчанию — `accounting_object_pilot_local_v3`. Подготовка переносит
только схему исходной базы, создаёт `pg_trgm` и применяет явные миграции.
Существующая база повторно не подготавливается. Для ещё одной чистой пробы
укажите новое имя `-Database accounting_object_pilot_<суффикс>` в обеих
командах. Запуск проверяет схему через `ddl-auto=validate`.

Первый запуск атомарно создаёт цеха `PILOT-A`, `PILOT-B`, изделия
`PILOT-01`, `PILOT-02`, типы ФИФО / ЛИФО / СКЕ и два документа:

| Документ | Дата | Цех / изделие | Результат |
| --- | --- | --- | --- |
| ПРОБА-У-001 | 01.10.2026 10:00 | PILOT-A / PILOT-01 | ФИФО |
| ПРОБА-К-001 | 02.10.2026 10:00 | PILOT-A / PILOT-01 | ЛИФО; текущий тип перед корректировкой — ФИФО |

Последующий запуск сохраняет изменения пользователя.

Форма номенклатуры также требует чтения групп, типов и значений атрибутов,
строк атрибутов и привязок КСУ. Эти права включены в новые примеры пилота.
Для ранее созданной базы v3 они добавлены 07.10.2026 отдельным скриптом
`scripts/accounting-object-pilot-nomenclature-read-grants.sql`.

### Запуск из IntelliJ IDEA

В проект добавлена отдельная конфигурация **Пилот объектов учёта (Maven)**
в каталоге `.idea/runConfigurations/`. Выберите её в списке
Run. Это Maven-конфигурация с целью `spring-boot:run`: она компилирует приложение
перед запуском, в том числе после `clean`. Maven Runner должен использовать JDK 21;
рабочий каталог, профиль и база v3 уже заданы. Если конфигурация не появилась, откройте
**Run → Edit Configurations…** или повторно откройте проект.

Пароль берётся из игнорируемого файла
`config/application-accounting-pilot-idea.local.properties`, подготовленного
из существующего файла пароля учётки. Он нужен для этой конфигурации;
исходный `application.properties` менять не требуется. Одновременно с запуском
через скрипт эту конфигурацию не запускайте: оба используют порт 18080.

## Что попробовать

1. В **Справочниках** откройте **Типы учёта**.
2. В **Производстве** откройте **Объекты учёта номенклатуры**. История цеха А
   содержит две записи со ссылками на два вида документов.
3. В поле **Представление** выберите **Срез последних** и задайте **На дату**: на 01.10.2026 10:00 ожидается ФИФО,
   на 02.10.2026 10:00 — ЛИФО. Граница включительная.
4. В **Установках объектов учёта** создайте документ цеха Б с изделием
   PILOT-01 и типом СКЕ. Введите номер и дату. История цеха А не меняется.
5. В **Корректировках объектов учёта** создайте документ цеха Б на более
   позднюю дату. Подбор предлагает объекты выбранного цеха на дату документа
   и показывает текущий тип. Укажите новый тип ФИФО.
6. Повторно откройте корректировку: текущий тип — СКЕ, новый — ФИФО.
   Собственный набор корректировки исключается при сравнении.
7. Поставьте дату до установки или смените цех. Текущий тип пересчитывается;
   отсутствие объекта на дату вызывает отказ сохранения. Черновые строки
   и выбранный новый тип сохраняются в форме.
8. Повторное сохранение документа заменяет его набор без роста истории.
   При одинаковых датах выигрывает последний записанный набор, затем номер строки.
9. Вторая первоначальная установка той же пары запрещена даже при наличии
   только будущих записей. Повторы изделия внутри документа тоже запрещены.
10. Удаление корректировки возвращает срез к установке. Если удалить установку,
    оставив корректировку, новая установка пары запрещена. После удаления всей
    истории пары установка снова разрешена.
11. Контроль самостоятельного регистра: в **Ценах номенклатуры** создайте две
    цены изделия на разные даты и измените ресурс первой записи. Здесь документ
    регистратор не требуется.

## Права и ограничения

- Права документов и регистра независимы. Для удаления документа требуется
  разрешение удаления его строк регистра. Без чтения документа подпись и ссылка
  маскируются, разрешённое чтение самого регистра продолжает работать.
- Учётка имеет полный доступ к локальному примеру. Новые документы и регистр
  используют права на вид сущности. Построчные права регистра по цехам не включены.
- Дата — без часового пояса, точность до миллисекунды. Номер вводится вручную
  и уникален в пределах вида документа.
- Подбор корректировки ограничен 200 объектами одного цеха; превышение вызывает
  явный отказ. Данные не обрезаются молча.
- Нужна минимум одна строка; для удаления последней удаляется документ.
  Прямой CRUD строк регистра закрыт.
- Команды блокируют цех на время транзакции: параллельные изменения разных
  изделий одного цеха сериализуются.
- Отчёт, экспорт и production-развёртывание — отдельный объём.
  Готовность пилота не закрывает Г0–Г8.

сообщения об отказах и следующий полезный сценарий.

## Диагностика отказов доступа (2026-10-07)

При отказе открытия или сохранения формы показывается диалог «Доступ запрещён»:
действие, известная причина и кнопка «Скопировать сообщение». Например, отсутствие READ типов
атрибутов указывает «Нет права чтения: „Типы атрибутов“». Это первая отказавшая
проверка: после назначения права может обнаружиться следующая зависимость.

Кнопка копирует тот же понятный текст, который показан пользователю, для передачи
администратору. При запрете буфера обмена браузером показывается поле для ручного
копирования. Пользователь с
`ROLE_ADMIN` видит раздел «Подробнее»: причину, операцию, технический ключ
проверки, сущность, пользователя и Trace ID, если он создан. Код диагностики
также записывается в журнал приложения; при включённой телеметрии — в SECURITY
событие `ui:access-denied`. Код диагностики доступен в административных подробностях;
основной текст сообщения и его копия содержат только понятную пользователю причину.

Отказ RLS обозначается отдельно как ограничение доступа к данным. Для старых
исключений без структурированной причины используется общее сообщение.
Скрытая или отсутствующая запись при открытии по адресу остаётся неразличимой.
При отказе сохранения карточка остаётся открытой с введёнными данными.

Для получения нового поведения перезапустите приложение обычной командой
запуска пилота: изменены Java-модули. Назначать дополнительные права для
включения сообщений не требуется; подробности требуют административной роли.

## Редактор запросов: права на поля отменены (2026-10-07)

Для запроса `select a.code as code, a.name as name from AccountingType a`
достаточно чтения сущности AccountingType и применимых ограничений RLS.
Отдельные права на code, name, id, version и поля аудита не нужны. Редактор
проверяет доступ к сущностям во всех частях запроса; существующие права пилота
на AccountingType позволяют выполнить этот SELECT после перезапуска приложения.
Решение действует для всех каналов: [ADR-0018](decisions/ADR-0018-no-field-permissions.md).

## Стандартные списки регистров — 2026-10-09

После перезапуска «Объекты учёта номенклатуры» и «Цены номенклатуры» открываются
через общую ListForm. В поле «Представление» переключайте историю / срез;
в срезе обязательно задайте «На дату». Фильтры измерений ограничивают кандидатов,
а фильтры ресурса / периода проверяют победителя: они не возвращают более старую
запись вместо не подошедшей последней. Смешанное «ИЛИ» между этими фазами требует
истории или разделения условий. Группировка списка в этой итерации выключена.

**Быстрый фильтр периода убран (2026-10-11).** У колонки «Период» больше нет строки
быстрого фильтра под заголовком: диапазон даты-времени широкий и перекрывал сам список.
Возможность отбора сохранена — период остаётся колонкой, условие по нему задаётся
через «+ Условия», а дата среза — контролом «На дату». Правило объявлено в самом
регистре (`@FieldMetadata(inlineFilter = false)` у периодических базовых классов),
поэтому форма выбора того же регистра выглядит так же: колонка есть, строки фильтра под ней нет.

**Кнопки записи (2026-10-11).** У самостоятельного регистра «Цены номенклатуры» в списке есть
«Создать»: запись здесь не требует документа. У подчинённого регистра «Объекты учёта
номенклатуры» кнопок создания, изменения и удаления в списке нет: строку формирует и заменяет
документ-регистратор, а ручная строка была бы затёрта при его пересохранении; изменить можно
ключ записи отдельной командой. Если «Создать» у самостоятельного регистра выглядит
недоступной, причина названа в подсказке кнопки. Чаще всего это отсутствие права на операцию:
фикстура пилота выдаёт права при первой подготовке базы и не переписывает существующие строки,
поэтому база, подготовленная раньше, чем фикстура объявила ключ, остаётся без него. При запуске
пилота фикстура печатает в журнал отсутствующие объявленные права, называя их ключи
(`ENTITY:<Имя типа>`); назначает право администратор, а не фикстура — намеренно снятое право
не возвращается при запуске молча.

«Виды» сохраняют колонки, отборы, режим и дату. «Скопировать ссылку» также
переносит состояние списка. При открытии ссылки права и доступность значений
проверяются снова; недоступный элемент отбора нужно выбрать заново.

В обычной карточке сохранённой цены измерения / период недоступны для изменения,
ресурс «Цена» редактируется согласно правам. Для смены ключа выберите строку
и нажмите «Изменить ключ записи». В отдельном окне доступны только измерения
и период. Отмена не меняет строку; сохранение сохраняет её ID и ресурсы.
У подчинённого регистра сохраняются регистратор, номер строки и порядок регистрации.
Документ при этом не пересохраняется. Новая запись может исчезнуть из текущего отбора.

Администратор явно назначает EXECUTE именованной операции смены ключа нужного
регистра. Технические ключи операций:
`REGISTER:org.ip.model.NomenclaturePrice:CHANGE_KEY` и
`REGISTER:org.ip.model.NomenclatureAccountingObject:CHANGE_KEY`.
Также нужны чтение / изменение данных самого регистра и применимые RLS-права.
Регистрация действий не выдаёт эти права существующей учётке accounting-pilot.
Без отдельного права кнопка недоступна; текст подсказки объясняет причину.

**Запись цены на дату (2026-10-13).** Регистр «Цены номенклатуры» объявляет `keyWriteAllowed`
([ADR-0023](decisions/ADR-0023-register-key-write.md)): цена по полному ключу `(номенклатура, дата)`
пишется командой регистра, а не решением приложения «создать или обновить». Прикладной путь —
`NomenclaturePriceService.setPrice` / `changePrice` / `removePrice`: отсутствующая строка создаётся,
повтор с той же ценой ничего не меняет (версия и аудит не растут), проверяемая версия отказывает,
а не затирает чужое решение, удаление требует версии. Технические ключи операций —
`REGISTER:org.ip.model.NomenclaturePrice:SET_KEY` и
`REGISTER:org.ip.model.NomenclaturePrice:DELETE_KEY`; их, как и `CHANGE_KEY`, назначает
администратор — регистрация операции грантов не выдаёт, поэтому база, подготовленная раньше этих
объявлений, останется без них, и вызов отказал бы до записи. Обычная карточка цены по-прежнему меняет
ресурс через canonical CRUD: это отдельный канал, и ключ записи в нём не меняется. Отдельного действия
формы «записать цену на дату» пока нет — оно появится вместе с пользовательской пробой этой команды.

Проба: измените цех / номенклатуру / период одной подчинённой записи, проверьте
тот же ID и прежний регистратор. Затем пересохраните документ-регистратор:
пилот заново очищает и формирует его набор через onSave, поэтому ручная правка
заменяется данными документа. Это выбранная прикладная политика данного пилота.
Ожидаем обратную связь по удобству списка и отдельного окна смены ключа.

### Лист пользовательской пробы

Пробу выполняйте на базе пилота, на тестовых документах и ценах.

| Шаг | Ожидаемый результат |
| --- | --- |
| История и срез на две разные даты | История показывает все записи; срез — одну последнюю на группу измерений |
| Открыть список «Цены номенклатуры» | Колонка «Период» без строки быстрого фильтра; «Создать» доступна, дата среза — в поле «На дату» |
| Открыть список «Объекты учёта номенклатуры» | Только просмотр: «Создать», «Изменить» и «Удалить» отсутствуют, доступна команда «Изменить ключ записи» |
| Отбор ресурса, которому не отвечает последняя запись | Группа исчезает; более старая запись не подставляется |
| Сохранить вид, открыть заново, скопировать / открыть ссылку | Те же режим, дата, колонки и отборы |
| Изменить ресурс сохранённой цены | Ресурс меняется; измерение и период в обычной карточке закрыты |
| Открыть «Изменить ключ записи», изменить значения и отменить | Запись не меняется |
| Сохранить новый ключ независимого регистра | Тот же ID и ресурс; при совпадении чужого ключа — понятный отказ |
| Сохранить новый ключ подчинённого регистра | Тот же ID, ресурс, регистратор, номер строки и порядок регистрации |
| Пересохранить документ после ручной правки регистра | Набор заново соответствует документу, дубликатов нет |
| Два окна одной записи: сохранить ключ в первом, затем во втором | Второе сохранение требует обновления записи и не затирает первое |

Для замечания достаточно номера шага и текста кнопки «Скопировать сообщение»
либо снимка экрана. Положительная оценка фиксируется после вашей пробы.

### Автоматическая PostgreSQL-проверка Р8

```powershell
.\scripts\register-r8-postgresql.ps1
```

Скрипт создаёт новую базу `g3_register_test_r8_<случайный суффикс>` и запускает
гонки ключа / замены набора / удаления / append / уникальности, прежние проверки
RecorderSetWriter и интеграционный пилот на PostgreSQL. Рабочая база из локальной
конфигурации используется только как источник настроек подключения. Её таблицы
не являются целью create-drop. Новая тестовая база оставляется для диагностики.
