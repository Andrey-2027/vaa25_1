# AF3.8: интеграция панели отборов и периода

Дата: 06.11.2026. Реализация выполнена; проверки ограничены согласованным объёмом.
Владелец отложил полный прогон приложения и финальную визуальную проверку
компактного режима. Полная визуальная приёмка этапа не заявляется.

## Реализация

- Панель всегда над списком и выбором. По умолчанию поля вертикальные;
  явные горизонтальные группы адаптируются к ширине окна, подписи могут быть
  в строку с полем (по умолчанию) или сверху.
- Подписи и типы редакторов берутся из метаданных. Общие условия используются
  в списке и выборе; ограничения выбора действуют в автокомплите и диалоге.
- Обязательный отбор блокирует создание до заполнения. Фиксированное ограничение
  открытия имеет приоритет и показано только для чтения с пояснением.
- Типизированный Filter.eq проверяет путь и тип. В новую карточку переносятся
  прямые равенства, включая необязательные; период, contains и произвольные
  условия не превращаются в значения реквизита.
- Общий PeriodField подключён к панели и фильтрам дат/даты-времени в шапке.
  Старый DateTimeRangeFilter удалён. Пресеты: сегодня, текущая неделя,
  текущий месяц, текущий квартал, сбросить. Ввод даты задаёт время автоматически.
- Переведены PrdSpec и ReceivingDocument. Семейство регистров использует
  PeriodField в истории и «На дату» в срезе; период истории не ограничивает срез.
- inlineFilter удалён из FieldMetadata и базовых классов регистров;
  доступность фильтра в шапке задаётся свойством колонки формы.
- Значения панели между открытиями не сохраняются (решение О7).

API и примеры: [панель отборов](../../forms/filter-panel.md).

## Браузерная проверка

Приложение запущено на `http://localhost:18080/`, профиль accounting-pilot,
отдельная копия БД `accounting_object_pilot_af34_20261106`.
Исходная БД не изменялась. Тестовые записи AF38 оставлены в копии для просмотра.

- ReceivingDocument: без журнала создание недоступно; выбор журнала разрешает
  создание и ограничивает строки. Период и цех совместно фильтруют список.
  Новая карточка получает журнал и цех, но не период; закрыта без сохранения.
- Обычное окно 1280px и узкое 760px: горизонтальной прокрутки страницы нет;
  всплывающий период в шапке доступен, высота шапки после применения стабильна.
- История цен: ноябрь включает 30 ноября и исключает полночь 1 декабря.
  Срез на 2 декабря выбирает декабрьскую цену независимо от ноябрьского периода.
  Возврат в историю восстанавливает диапазон; сброс показывает обе записи.
- Регистр объектов учёта: четыре строки истории превращаются в два последних
  значения по ключам. Команды записи для регистра только для чтения отсутствуют.
- Горизонтальные группы и конфигурация PrdSpec проверены автоматическими
  тестами; отдельная браузерная приёмка этих сценариев не заявляется.

## Граница дня и артефакты

PostgreSQL округляет наносекундный конец дня до следующей полуночи.
Поэтому JPA и нейтральное дерево используют GE начала и LT начала следующего
дня; модель редактора сохраняет LocalTime.MAX. Обычное точное время остаётся
включённой границей. Исправление внесено в FilterGrid и ContextFilterConditions.
SQL-подтверждение: `af38-timestamp-boundary.log`.

Финальные артефакты установлены в обычный и изолированный Maven-кэш до запуска
приложения. Отпечатки затронутых модулей обновлены в local-dependencies.json.

## Отложенные и отдельные ограничения

- Полный прогон и финальная визуальная проверка компактности отложены владельцем.
- Частичный широкий запуск `af38-application-full.log` содержал ошибки HTTP
  из-за запрета loopback в песочнице; полного зелёного результата нет.
- В матрице зависимостей добавлено обоснование builder → data для общих отборов.
  Ещё два обнаруженных ребра вне этой реализации не исправлялись:
  builtin → data (CatalogOwnerContext) и config → metadata.annotation (коллектор AF3.3).
- Расширенный запуск core (`af38-core.log`) выявил расхождение
  EffectiveStandardMetadataTest: ожидалось number, получен пустой набор.
  Код представления/поиска вне AF3.8 не менялся; отдельная проверка исходной
  базы для определения происхождения этого расхождения не проводилась.
- Bootstrap выявляет отдельный дрейф platform-report-vaadin (33 → 34 файла).
  Его отпечаток в рамках AF3.8 не обновлялся.
- Обязательный журнал ReceivingDocument отражён в эталоне маршрутов:
  открытие списка по URL без контекста недоступно по действующей политике.
  Передача контекста через URL остаётся задачей RouteContextCodec.
