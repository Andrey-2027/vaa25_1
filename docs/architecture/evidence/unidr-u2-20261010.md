# UniDR U2: источник, отборы и защищённый запуск

Дата: 2026-10-10. Продолжение [U1](unidr-u1-20261010.md) и [U0](unidr-u0-20261010.md).
Личные варианты и сохранение по-прежнему отложены по запросу пользователя.

## Карточка решения

| Пункт | Решение |
| --- | --- |
| Цель | Выполнить типизированную настройку U1 на позициях накладных через действующие права и RLS |
| Режим | Серверный пакет пилота U2; пользовательская проба редактора требует следующих этапов |
| Основание | Явный запрос «U2: источник, отборы и защищённый запуск» |
| Потребитель | Будущий сборщик U3 и редактор U4 |
| Входит | Один источник, параметры запуска, фиксированные/параметризованные отборы, защищённый выбор ссылок, полный scalar dataset, квота/worker и состояние результата |
| Отложено | Личные варианты, таблицы хранения, произвольный SQL/HQL, renderer/экспорт U3, маршрут и UI U4 |
| Гарантии | Серверный allow-list, C5 и RLS до SQL, повторная проверка ссылок, отсутствие частичных итогов, отдельная read-only транзакция, изоляция результатов |
| Критерий завершения | Реальные параметры дают полную разрешённую выборку в пределах лимита либо структурированную ошибку; значимые отказы проверены |
| Следующий пакет | U3: сборщик DynamicReports, предпросмотр и экспорт из одного результата |

## Реализация

Новый код находится в прикладном `org.ip.unidr`. Новых зависимостей Maven,
JPA-сущностей, repository и изменений таблиц приложения нет.

| Тип | Назначение |
| --- | --- |
| `UniDrRunRequest` | Неизменяемая настройка, фактические значения параметров и зона пользователя; без поля владельца |
| `UniDrRunParameterResolver` | Проверяет ввод, вычисляет CURRENT_MONTH по моменту/зоне запуска, применяет FIXED и обязательность из U1 |
| `UniDrQueryAdapter` | Превращает разрешённые ID полей/операции в серверный HQL с отдельными типизированными bindings и transient ReportTemplate без бэндов |
| `UniDrReferenceService` | Поиск и повторная проверка ID через APP_API EntityLookup → существующий canonical read; наружу выходят только ID и подпись |
| `UniDrQueryService` | Проверяет владельца/ссылки/схему, выполняет guarded query в отдельной read-only транзакции и возвращает отделённые строки |
| `UniDrAccess` | Проверка feature flag, аутентификации, согласованности текущего субъекта; запрет anonymous/system/RLS bypass |
| `UniDrRunService` | Существующие ReportTaskExecutor и общая ReportRunQuota; snapshot авторизации, освобождение слота, session/revision/close |
| `UniDrRunResult` | Результат одного запуска с UUID, владельцем, определением, временем и эффективными параметрами; общий кэш отсутствует |
| `UniDrConfiguration` | Условная регистрация бинов по app.unidr.enabled; по умолчанию не включена |

Общий `ReportQueryAssemblyService` получает только механическую адаптацию двух
проверок `IdentifiableEntity<?>` к текущему nongeneric `IdentifiableEntity`.
Это необходимо для компиляции используемого пути после миграции identity;
сборка запросов и поведение старого UDR не изменены. Другие существовавшие
изменения этой рабочей копии не принадлежат U2.

## Чтение и условия

Источник `receiving-items` v1 возвращает одну строку на `ReceivingDocumentItem`:
ID строки и документа, номер/дату, ID/подписи обоих цехов и номенклатуры,
код номенклатуры, ID/подпись единицы, BigDecimal количества — 14 scalar-полей.
Их имена, типы и количество сверяются со схемой сборщика перед выполнением.

Независимые JOIN к документу, обоим цехам, номенклатуре, единице и журналу
сохраняют фактические Hibernate-фильтры и проверку чтения связанных типов.
Используются полные действующие assembly/executor: guard и ReportReadAuthorizer
проверяют запрос; executor повторяет допуск перед SQL и включает RLS.
UniDR не добавляет собственную трактовку grants или обход защиты табличной части.

Условия объединяются через И. Значения не вставляются в HQL:
DATE → LocalDate, REFERENCE → Long, DECIMAL → BigDecimal. Два scalar bindings
представляют один период пользователя: существующий guard требует точных имён
параметров, что было подтверждено в U0. Пустой необязательный параметр не
создаёт условие; явно переданный пустой список очищает необязательный FIXED.
Неизвестные параметры, неверные типы, неполный/обратный диапазон и недопустимые
значения отвергаются до запроса источника. Сам adapter тоже проверяет значения
и не позволяет напрямую опустить обязательные period/unit.

`period` обязателен всегда. `unit` обязателен при SUM/AVG/MIN/MAX количества;
чистый COUNT_ROWS может включать разные единицы. `recipient` необязателен.
Параметры дополнительных отборов обязательны. ID ссылок повторно читаются
через canonical lookup в транзакции запуска, включая фиксированные ссылки.
Не найденная и скрытая ссылка дают одинаковый REFERENCE_UNAVAILABLE.
Поиск ссылок разрешает только поля источника, до 100 вариантов и 200 символов
поисковой строки; произвольный Java-тип клиент передать не может.

Сначала сортируются пути всех групп с их ID, затем дополнительные сортировки,
затем ID позиции. Группа использует ID независимо от подписи. Например,
`r.name, r.id, n.code, n.id, d.date, i.id` сохраняет непрерывность групп даже
при одинаковом названии цехов. Сортируются серверные пути, а не SELECT aliases:
это совместимо с текущим Hibernate SQM/C5 walker, проверенным в U0.

## Ограничения и жизненный цикл

Бины активируются `app.unidr.enabled=true`; при отсутствии/false зависимостей
UniDR не требуется. Дополнительно флаг проверяется на входах сервисов, в worker
и перед выдачей результата. Флаг не заменяет права чтения.

| Настройка | По умолчанию | Допустимый диапазон |
| --- | --- | --- |
| `app.unidr.max-rows` | 5000 | 1–5000 |
| `app.unidr.timeout-ms` | 30000 | 1–120000 |

Неверные лимиты останавливают создание бинов. Используются общий ограниченный
worker и общая квота отчётов приложения. Переполнение квоты/очереди имеет
отдельные BUSY/QUEUE_FULL. Слот освобождается при успехе, ошибке и отклонении
очередью. Отмена уже поставленного задания удерживает слот до обработки worker.

Чтение начинается в новой read-only транзакции с timeout, независимо от
транзакции вызывающего кода. Executor получает limit + 1 и timeout; при лишней
строке весь результат отвергается с LIMIT_EXCEEDED, не обрезается. Действующий
executor задаёт JDBC timeout и PostgreSQL SET LOCAL statement_timeout.
Внешний набор не содержит JPA-сущностей или lazy-ссылок; транзакция заканчивается
до построения будущих PDF/XLSX.

TIMEOUT распознаётся по JPA/Hibernate/Spring timeout и SQLSTATE 57014;
ACCESS_DENIED, QUERY_REJECTED, QUERY_FAILED и SCHEMA_MISMATCH имеют безопасные
русские сообщения. Причина сохранена для серверной диагностики; UI должен
показывать message/code, а не cause/stacktrace. Пустая выборка — успешный результат
с сообщением «По выбранным условиям данных нет».

UI в U4 должен владеть отдельным `UniDrRunService.Session`, вызывать `start`,
`invalidate` при изменении настройки/параметров и `close` при detach. Ревизия
не позволяет позднему ответу заменить новый результат. Чтение latest и запуск
проверяют текущего владельца; разные session-объекты не разделяют результаты.
Ticket.cancel отменяет публикацию, а не обещает прерывание работающего SQL.
Session.close допустим в callback detach без SecurityContext и только очищает
состояние. HTTP endpoint или доступ к результату по UUID в U2 не вводится.

## Проверки и воспроизведение

Запускать из корня на JDK 21, передав установленный Maven:

```powershell
./scripts/run-unidr-u2.ps1 -MavenCommand '<path-to-mvn.cmd>' -JavaHome '<JDK-21>'
./scripts/run-unidr-u2.ps1 -MavenCommand '<path-to-mvn.cmd>' -JavaHome '<JDK-21>' -Postgres
```

Первый прогон включает регрессию U1 и общей сборки запросов UDR. Скрипт компилирует UniDR, прикладную модель
и реально используемые зависимости из исходников через javac/sourcepath,
затем только соответствующие тесты. Production-классы и тесты находятся в
разных обычных output-директориях. Mockito запускается через startup javaagent.
Это изолированный gate; он не подменяет full application compile/test.

Postgres-прогон читает локальный JDBC URL из `config/application-local.properties`,
не выводит пароль и создаёт только `unidr_u2_<UUID>`. currentSchema/default_schema
указывают на эту схему. После проверки она удаляется; предусмотрен shutdown hook.
Основная схема и данные пользователя не изменяются.

| Проверка | Результат |
| --- | --- |
| Scoped compilation UniDR и реальных source dependencies | PASS, Java 21 |
| Модель/JSON U1 | 49 PASS |
| Разрешение параметров | 10 PASS |
| Query adapter | 2 PASS |
| Query service: extra row, empty, schema, timeouts и безопасные ошибки | 10 PASS |
| Worker/quota/session/access | 12 PASS |
| Условная конфигурация и лимиты | 4 PASS |
| Реальная БД/H2, canonical lookup, C5, RLS, отдельная read-only транзакция | 8 PASS |
| Итого UniDR unit/H2 | **95 PASS**, без пропусков |
| Регрессия общей сборки UDR: VisualFilter/VisualParameter/VisualQuery | **7 PASS** |
| Всего основной прогон | **102 PASS**, без пропусков |
| Те же интеграционные сценарии на PostgreSQL 17.10 | **8 PASS**, временная схема удалена |

На фикстуре: 6 позиций в выбранной единице, сумма 36; COUNT_ROWS без единицы
видит 7 позиций. Закрытый журнал, закрытый цех сдатчика/приёмщика и иной период
не попадают в выборку. Фиксированный/параметризованный отбор по количеству
совместно с recipient оставляет позицию с количеством 4. Лимит 6 проходит,
лимит 5 отвергает выборку. Снятие ENTITY-read у Workshop после lookup останавливает
запуск до SQL источника. Проверены одинаковые подписи групп с различными ID.

PostgreSQL: `unidr_u2_19779c832fb44ead95063765d6d0bb4b`; создание и удаление
подтверждены `postgresql-environment.txt` и `postgresql-cleanup.txt`.

Таймауты проверены инъекцией соответствующих исключений; намеренно тяжёлый SQL
и принудительный реальный server timeout в этой приёмке не запускались.
Проверка lifecycle использует настоящий ReportTaskExecutor с управляемым
детерминированным Executor. Пробу Vaadin detach/preview/export оставляем U3/U4.

Локальные журналы: `outputs/unidr-u2/test.log`, `compile-scoped.log`,
`compile-tests.log`, `source-sql-h2.log`; PostgreSQL — отдельные environment,
SQL, cleanup и test logs в той же папке.

Общая сборка приложения блокировалась 23 ошибками миграции IdentifiableEntity
до начала U2. Из них исправлены две в необходимой общей сборке запросов.
Повторный `mvn -o -DskipTests compile` оставляет **21 существующую ошибку**
в формах, print action и регистрах; классы UniDR среди ошибок отсутствуют.
Журнал: `outputs/unidr-u2/compile-main-final.log`. Full gate не считается пройденным.
Эти ограничения не позволяют объявить
всё приложение или пилот редактора готовыми к пользовательской пробе.
