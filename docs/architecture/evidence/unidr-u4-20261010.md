Дата: 2026-10-10. Продолжение [U3](unidr-u3-20261010.md).

| Пункт | Решение |
| --- | --- |
| Цель | Настроить и сформировать отчёт по позициям накладных без редактирования JSON |
| Режим | Редактор пилота; приёмка всего приложения U5 и пользовательская проба U6 отдельно |

## Экран и параметры

Отдельный маршрут `/unidr`, флаг `app.unidr.enabled=true`; по умолчанию пилот
выключен. Старый редактор UDR не меняется. UniDR использует обычные Vaadin
компоненты и локальный CSS `.unidr-editor`, без Form API и новой persistence-модели.

В настройке задаются название, поля и подписи колонок, агрегации, до трёх
группировок с порядком, представление «детали»/«только итоги», общий итог,
отборы, сортировки, независимые границы строк/колонок и чередование фона.
Настройка сворачивается; значения для запуска расположены над результатом.
CSS переводит две колонки в последовательное расположение при ширине до 1050px;
фактический вид на узком экране пока не проверен.

Раздел «Параметры» настраивает подпись и начальное значение: пустое, заданное,
для периода также текущий месяц. Последний вычисляется в часовом поясе браузера;
если браузер не передал допустимую зону, используется серверная.
Значение текущего запуска не переписывает default настройки.

Параметры источника: период, единица измерения и необязательный цех-приёмщик.
Их тип/назначение фиксированы. Дополнительный параметр создаётся для выбранного
поля/оператора сразу с отбором. Существующий совместимый параметр можно привязать
к нескольким отборам. Удаление параметра явно удаляет его связанные отборы.
Условия соединяются через И. Скалярные значения вводятся DatePicker или
BigDecimalField; сущности выбираются ComboBox по подписи через canonical lookup.
Ручного ввода ID нет. Начальная ссылка разрешается через
`UniDrReferenceService.selected`, с той же проверкой доступа и видимости, что lookup.
Недоступное начальное значение сохраняется как невалидное, не превращаясь в пустой
необязательный отбор. Состав, типы, диапазоны и обязательность проверяются сервером.

## Запуск и ресурсы

Экран использует защищённую сессию U2, worker и квоту U3. В фоновый запуск
передаётся HttpSession RequestAttributes, а не завершившийся servlet request.
Изменение настройки или значений инвалидирует ревизию и ссылки скачивания.
Предыдущий preview остаётся с явной пометкой; старый результат не публикуется
после отмены или изменений. Detach закрывает сессию и снимает polling.
Отмена прекращает ожидание/публикацию, принудительная остановка SQL/DR не обещается.

Preview и ссылки используют Vaadin 25 DownloadHandler и тот же JasperPrint U3.
На HTTP-запросе проверяются владелец результата и флаг пилота, включая кэшированный
файл. Инвалидированная ссылка отвечает 410, отказ доступа — 403; выдаётся
`Cache-Control: no-store`. Современные element src/href управляют регистрацией
ресурсов. Общего публичного хранилища экспортов нет.

Сброс и выход предупреждают о потере изменений; переход внутри Vaadin и закрытие
страницы обрабатываются отдельно. Личные варианты отсутствуют по запросу пользователя.
Ошибки валидации показываются рядом с запуском; неожиданные ошибки имеют безопасный
текст и серверный журнал.

## Проверки

```powershell
./scripts/run-unidr-u4.ps1 -MavenCommand '<path-to-mvn.cmd>' -JavaHome '<JDK-21>'
```

При нестандартном Maven cache передать `-LocalRepository '<path-to-repository>'`.
Скрипт работает offline, компилирует реальные исходники UniDR и используемые
зависимости. Для javac JAR копируются без изменения содержимого в workspace:
это обходит Windows sandbox ZIP-close ошибку доступа к пользовательскому cache.
Координаты и версии зависимостей не менялись.

| Проверка | Результат |
| --- | --- |
| Компиляция исходников экрана и его тестов | PASS |
| `bootstrap-local-dependencies.ps1 -ValidateOnly -Offline` | PASS: граф, координаты, workspace и fingerprints; manifest не изменён |
| U1–U4, включая источник/H2/C5/RLS и регрессию сборки запросов UDR | **155 tests, 0 failures, 0 errors, 0 skipped** |
| Новые проверки экрана и HTTP download callbacks | 14 PASS, входят в 155 |
| Самостоятельный UI-стенд | Spring/Vaadin запущены, frontend bundle собран |
| Визуальная проверка UI | Не завершена: управление Chrome остановлено пользователем; встроенный браузер дважды отказал с `failed to write kernel assets: ... (os error 3)`, включая повтор после reset |
| Полная сборка приложения | Ранее зафиксированное ограничение: 21 ошибка миграции IdentifiableEntity вне UniDR; полный gate не заявляется пройденным |

Проверки экрана включают исходную настройку, создание числового/ссылочного
параметра и default, повторное использование совместимого параметра, удаление
связанных отборов, порядок групп, оформление, недоступную ссылку, обязательную
единицу до очереди, подавление позднего результата, устаревший preview, reset/close
и выключенный пилот. Проверки download охватывают владельца, флаг, устаревшую
ссылку, кэш и безопасный отказ. Это проверки настоящих Vaadin компонентов без
браузера; они не заменяют проверку layout и пользовательскую приёмку.

Журналы: `outputs/unidr-u4/gate.log`, `test.log`, `compile-scoped.log`,
`compile-tests.log`, `smoke-server.log`, `baseline-validation.log`. Предшествующий baseline полной компиляции:
`outputs/unidr-u4/compile-baseline.log`.

## Повторяемый стенд для проверки экрана

После scoped gate, при установленных Node.js и frontend dependencies:

```powershell
./scripts/run-unidr-u4-smoke.ps1 -JavaHome '<JDK-21>' -NodeFolder '<Node.js-folder>'
```

Открыть `http://127.0.0.1:8086/unidr`. Это исключительно loopback-стенд
`src/test/java/org/ip/views/unidr/smoke/UniDrUiSmokeApplication.java`: фиксированный
пользователь, фиктивный источник и справочники, без рабочей БД. Экран, worker,
DynamicReports и экспорт настоящие. Этот стенд не доказывает авторизацию реального
приложения; она проверяется отдельными интеграционными тестами.

Начальный период — текущий месяц. Для фикстуры указать 01.10.2026–31.10.2026,
единицу «шт», цех не заполнять. Сформировать: шесть позиций, сумма количества 36,
счётчик 6. Проверить preview/PDF/XLSX; изменить порядок группировок, переключить
детали, добавить параметр количества «не меньше», задать значение и повторить
запуск. До нового запуска старый результат должен быть помечен устаревшим,
экспорт отключён. Затем проверить сворачивание настройки, узкую ширину,
предупреждение сброса и ухода. Эти браузерные действия пока остаются непроверенными.

В реальном приложении включить флаг, войти обычным пользователем и открыть
`/unidr`; требования к C5/RLS и ограничения источника описаны в evidence U2.
U5, практическая проба U6 и визуальная проверка U4 остаются открытыми.
