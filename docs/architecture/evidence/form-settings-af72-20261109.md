# AF7.2 — строгие новые формы и совместимость (09.11.2026)

## Реализованная политика О2

Новые строгие рецепты: standard-catalog-v4@4, standard-document-v3@3,
independent-register-v5@5 и independent-register-v6@6 (RLS).
Все прежние RecipeRef остаются доступны и сохраняют генераторы/отпечатки.
Рецепты AF4.1 тоже сохраняются: они ещё генерируют GridColumn; их вывод
нельзя было молча изменить ради завершения переходного периода.

Новые корни и строки получают runtime-аннотацию `@FormSettingsOnly`.
Она не наследуется: стандартная захваченная база может содержать старые настройки.
Проверяется каждый объявляющий класс, поэтому новая декларация в строгом классе
не может воспользоваться совместимостью его старой базы.

`MetadataConsistencyValidator` читает **явные** пары аннотаций из classfile через
имеющийся Spring ASM. Это различает отсутствие атрибута от явного false, пустой
строки, пустого массива или GridColumn(). Новых внешних зависимостей нет.

| Объявления | Строгий объявляющий класс | Прежний класс |
| --- | --- | --- |
| EntityMetadata.listColumns/selectColumns | ERROR FORBIDDEN_FORM_SETTING | WARNING LEGACY_FORM_SETTING, прежнее чтение |
| FieldMetadata.grid/readOnly, GridColumn | ERROR | WARNING, прежнее чтение |
| Lookup.entity/variant/fetch | ERROR | WARNING, прежнее чтение |

Ошибку строгого контракта нельзя погасить MetadataAllowance. Existing defaults
самих аннотаций не считаются пользовательскими объявлениями. Приоритеты чтения
конфигурации форм и прежние предупреждения двойного объявления не менялись.
FieldMetadata.grid/readOnly и Lookup.variant/fetch помечены Deprecated без удаления.

Генератор проверяет финальные файлы строгих рецептов до выдачи GenerationPlan;
строковые подписи и комментарии исключаются из этой проверки. В новых версиях
колонки корня — в ListColumns/SelectionColumns, таблицы строк — в bean
TableSectionCustomization внутри той же конфигурации. FormColumnDeclarations.none()
сохраняет явно пустую таблицу без перехода к автоматическому составу.
Состав полей формы строки остаётся независимым от таблицы.

FormDeadApiTest разбирает Java AST исходников приложения и examples. Допустим
только перечень прежних 148 деклараций в forms/legacy-form-declarations.txt;
в examples старые декларации не разрешены вовсе. Новый код вне этого репозитория
получает строгую проверку при выборе нового рецепта или явной FormSettingsOnly.
Неотмеченный старый класс остаётся входом совместимости, а не угадывается по дате.

   EffectiveStandardMetadataTest.numberingSearchAndPresentationNeedNoLocalInfrastructureDeclarations:
   поиск документа возвращает [] вместо [number]. Тот же метод падает на отдельной

   33/66e51a92… против 34/1aa43950… (bootstrap.log). Чужой отпечаток не менялся.

   FetchPlanRegistry из FormReadDependenciesIT. Этот файл не менялся в AF7.2.
   Общий прогон архитектуры прерван после этой ошибки; зелёным не объявляется

завершён. Проверка diff выполняется с cr-at-eol: исходные CRLF контрактов сохранены.

готовый экран не переделывался.
