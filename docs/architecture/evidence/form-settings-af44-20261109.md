# AF4.4 — обязательная команда миграции (09.11.2026)

## Объём

Владелец поручил только обязательный объём. Реализован перенос литеральных
`listColumns` / `selectColumns` из `@EntityMetadata` в аннотации существующего
или нового класса конфигурации форм. Явный состав сохраняется, включая совпадение
с автоматическим. Пустые массивы сохраняют прежний AUTO. Если старый выбор
наследовал явный список, его колонки записываются явно: новый контракт конфигураций
не наследует список в отсутствие `@SelectionColumns`.

Переходы явного состава на AUTO, флаг такого перехода, повторная миграция рабочих
моделей и перенос `examples/` исключены из этого этапа по указанию владельца.

## Использование

```powershell
.\scripts\entity-modify.ps1 migrate-forms -Project C:\work\consumer -Type com.example.model.Material -Out C:\work\forms-plan
# Проверить changes.diff, затем:
.\scripts\entity-modify.ps1 apply -Project C:\work\consumer -Plan C:\work\forms-plan
```

Планирование не меняет проект и не требует consumer classpath. План содержит
`changes.diff` и `form-migration.properties`: пути, исходные/новые хэши и тексты
UTF-8 в Base64, отметку отсутствовавшего файла, fingerprint манифеста.
Чтение плана сверяет содержимое, хэши и diff.

## Гарантии применения

- Все пути проверяются на выход за source root и переходы через ссылки.
- Все целевые файлы и их исходные хэши проверяются до первой замены;
  ожидавшийся новый файл должен отсутствовать.
- План пересчитывается из актуальных исходников: новые привязки, изменённые
  зависимости состава и неоднозначность конфигурации останавливают применение.
- Все новые тексты сначала подготавливаются во временных файлах; затем ещё раз
  проверяются все исходные хэши. Только после этого начинаются замены.
- Ошибка записи, исключение после замены или несовпадение итогового хэша
  восстанавливает исходные тексты всех затронутых файлов и удаляет созданные
  этим применением файлы. Проверка отката не использует повреждённый тестовый
  перехватчик записи. При невозможности восстановления сообщение перечисляет файлы.
- Полностью применённый план повторно ничего не меняет; частичное состояние
  считается конфликтом. Прежние однофайловые планы и команды остаются совместимы.

Ограничения: статический читатель, без выполнения Java и без компиляции consumer;
после применения нужен его build. Параллельная запись другим процессом после
последней проверки и аварийное завершение процесса/машины не входят в гарантию
отката. Условные/наследуемые объявления, выражения вместо литералов, конфликт
default-деклараций, несколько конфигураций назначения и занятый новый путь
получают отказ до записи. Новый класс создаётся в пакете сущности; остальные
аннотации и методы существующей конфигурации сохраняются.
