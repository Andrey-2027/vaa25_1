# UniDR U1: модель настройки и валидация

Дата: 2026-10-10. Статус: сокращённый U1 выполнен.

Пользователь запросил U1, затем уточнил: «пока без личных вариантов — потом их».
Поэтому выполнены модель, JSON v1, описание источника и проверка допустимости.
Таблица, JPA, repository, сервис владельца, сохранение и UI не добавлялись.
Хранение личных вариантов выделено в отложенный U1b.

## Карточка решения

| Пункт | Решение |
| --- | --- |
| Цель | Подготовить простую настройку отчёта, независимую от бэндов UDR, для последующих запроса и редактора |
| Режим | Подготовительный пакет пилота; U0 уже подтвердил чтение и рендер |
| Основание | Запрос U1 с явным исключением личных вариантов |
| Входит | Неизменяемые типы, JSON v1, серверное описание receiving-items, валидатор, начальный пример |
| Отложено | Сохранение и личные варианты; запрос/запуск U2; рендер U3; Vaadin U4 |
| Гарантии | Неизвестные поля/версии не теряются; операция проверяется по метаданным; значения запуска не подменяют настройку |
| Проверки | Round-trip, корректные сценарии, ошибочные версии/JSON/операции/параметры, неизменяемость |
| Критерий завершения | Начальный пример преобразуется в типизированное определение и обратно; неправильная настройка имеет структурированную диагностику |
| Практическая проба | JSON-пример и локальные тесты; пользовательская проба редактора требует U2–U5 |
| Следующий пакет | U2: источник, отборы и защищённый запуск |

Политика: `docs/architecture/development-delivery-policy.md`.
Локальный план: `docs/plans/unidr-pilot-plan.md`, уточнённый объём включён во все
этапы и сценарий первой пробы. Отложенный U1b не является условием этой пробы.

## Что добавлено

Всё размещено в прикладном `org.ip.unidr`; новые зависимости, платформенный API,
Spring-бины, маршруты и persistence scans не вводились. Классы UDR не менялись.

| Тип | Назначение |
| --- | --- |
| `UniDrDefinition` | schema/source version, заголовок, упорядоченные колонки, показатели, группы, отборы, параметры, сортировка, режим и общий итог |
| `UniDrDefinitions` | Начальная настройка «Количество по цехам и номенклатуре» |
| `UniDrSourceDefinition` | Серверные типы, подписи, aliases, ключи групп, пути сортировки, операции и требования параметров |
| `UniDrReceivingItemsSource` | Контракт первого источника: дата, накладная, два цеха, номенклатура, единица, количество, счётчик позиций |
| `UniDrSourceCatalog` | Реестр разрешённых сервером источников |
| `UniDrDefinitionValidator` | Проверка настройки и вычисление обязательности параметров |
| `UniDrDefinitionJsonCodec` | Строгое преобразование JSON v1 с проверкой модели на чтении и записи |
| `UniDrValidationException` | Список ошибок с кодом, путём настройки и русским сообщением |

Определение и вложенные значения — records с защитным копированием списков.
Группы/поля используют стабильные ID, не заголовки пользователя и не HQL-пути.
Поля ссылок имеют отдельные aliases подписи и ключа. Количество содержит связь
с полем единицы измерения. COUNT_ROWS — самостоятельный показатель `rowCount`.
Технический marker и видимая колонка ID для него не нужны.

Запрос в описание U1 не включён: конструирование и исполнение относятся к U2.
Метаданные соответствуют aliases, проверенным в U0; сверка с анализом итогового
запроса будет выполняться при подключении U2.

## Настройки и правила

- До трёх разных группировок, независимо от выбранных детальных колонок.
- Одна агрегация на поле; количество допускает SUM/AVG/MIN/MAX, `rowCount` — COUNT_ROWS.
- Summary требует показатель; details — поле или показатель. Синтетический счётчик не выбирается как обычная колонка.
- По каждому полю разрешены только операции из серверного описания. Отборы объединяются через И.
- Literal содержит явный тип и строки значений: ISO-даты, точные десятичные числа, положительные Long ID ссылок.
- ParameterRef содержит ID параметра. Проверяются объявление, тип, число значений и домен ссылки; два цеха могут использовать общий параметр, номенклатура и цех — нет.
- Параметры источника нельзя переназначить. Дополнительный отбор по уже связанному с параметром источника полю запрещён, чтобы не создавать независимые значения одного ограничения.
- `period` обязателен. `unit` обязателен при любом числовом итоге количества; для списка и COUNT_ROWS необязателен. `recipient` необязателен, пока не использован в дополнительном условии.
- Параметры дополнительных отборов обязательны. Неиспользуемые дополнительные параметры запрещены.
- Начальное значение задаётся NONE, FIXED или CURRENT_MONTH. CURRENT_MONTH допустим только для диапазона дат и пока хранится правилом; вычисление по зоне пользователя относится к U2.

В определении нет фактических значений последнего запуска, владельца, ID
сохранённого варианта, Java-типов ссылок или произвольных запросов.
FIXED означает явный дефолт настройки, а не скрыто сохранённый последний ввод.
Доступность реального ID и права пользователя этим валидатором не проверяются:
в U2 они проверяются существующим защищённым чтением и lookup-механизмом.

JSON ограничен 128000 символами и глубиной 32. Дубли ключей, лишние свойства,
неизвестные enum/type IDs, trailing tokens и неявные преобразования типов
запрещены. Неизвестная версия формата получает отдельную диагностику; миграции
и молчаливое удаление полей не выполняются. Ошибки Jackson не выводят входной текст.
Заголовки — 1–200 символов; списки настроек ограничены; десятичные константы —
до 30 значащих цифр и 12 знаков после точки, без экспоненциальной записи.

## Результаты проверок

| Проверка | Результат |
| --- | --- |
| Production-классы UniDR | Компилируются `javac --release 21` на зависимостях текущего POM |
| `UniDrDefinitionTest` | 32 проверки пройдены |
| `UniDrDefinitionJsonCodecTest` | 17 проверок пройдены |
| Итого | 49, ошибок 0, пропусков 0 |
| Начальный JSON-пример | Читается, совпадает с начальной настройкой, проходит round-trip |
| БД/JPA | Не изменялись; persistence исключён из текущего запроса |
| Общая Maven-компиляция приложения | Не проходит: 23 существующие ошибки в коде вне UniDR, связанные с миграцией `IdentifiableEntity` |

Общая сборка проверялась отдельно. В отличие от U0, текущий отказ возникает уже
в production compile. Эти исходники не исправлялись, прежнее свидетельство U0
не переписывалось. Успех 49 проверок не объявляется успехом сборки всего приложения.

`run-unidr-u1.ps1` разрешает текущий test classpath Maven offline, отдельно
компилирует только новые production-классы в `target/classes` и тесты в
`target/test-classes`, затем запускает два теста через Surefire. Он не использует
старые скомпилированные классы приложения для проверки модели и не требует БД.

## Повторный запуск

Из корня проекта, JDK 21 и подготовленные локальные зависимости:

```powershell
./scripts/run-unidr-u1.ps1 `
  -MavenCommand 'C:\Program Files\JetBrains\IntelliJ IDEA Community Edition 2025.2.3\plugins\maven\lib\maven3\bin\mvn.cmd' `
  -JavaHome 'C:\Program Files\Axiom\AxiomJDK-21'
```

Материалы:

- `examples/unidr/receiving-items-v1.json` — читаемый пример формата;
- `src/main/java/org/ip/unidr/model/` и `source/` — продуктовые классы;
- `src/test/java/org/ip/unidr/model/` — проверки;
- `outputs/unidr-u1/test.log`, `compile-scoped.log`, `compile-tests.log`, `dependencies.log` — изолированный прогон;
- `outputs/unidr-u1/compile-main.log` — исходный отказ общей сборки;
- `outputs/unidr-u1/receiving-items-v1.json` — JSON, записанный проверкой round-trip.

Настройка пока не переживает перезапуск через пользовательское хранилище:
сервис сохранения, владелец, optimistic locking и соответствующая приёмка
будут добавлены в U1b, когда пользователь вернёт их в объём.
