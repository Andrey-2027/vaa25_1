# UniDR: источник по запросу UDR

Дата: 2026-10-10. Продолжение [U4](unidr-u4-20261010.md).

## Карточка решения

| Пункт | Решение |
| --- | --- |
| Цель | Пользователь задаёт источник запроса, затем выбирает колонки, группы, итоги и параметры в UniDR |
| Режим | Следующая итерация пилота по прямому запросу пользователя |
| Изменение объёма | Снято ограничение первого пилота на единственный заранее заданный источник |
| Входит | Реальные редактор, конструктор и параметры UDR, динамическая схема, защищённый запуск, preview/PDF/XLSX |
| Отложено | Личные варианты и сохранение, native SQL, новый язык запросов, большие выборки |
| Проверка пробы | Удобно ли задать собственную выборку и настроить отчёт без структуры бэндов DynamicReports? |

## Как попробовать

Маршрут `/unidr`, флаг `app.unidr.enabled=true`.

1. Нажать **«Задать запрос…»**. Открывается существующий `ReportQueryEditor` UDR
   в `ReportQueryDialog`: текст запроса, проверка, пробное выполнение и конструктор.
2. Ввести, например:

   ```sql
   select n.code as code, n.name as name
   from Nomenclature n
   where n.name <> :excludedName
   order by n.name
   ```

3. Через **«Параметры отчёта…»** задать `excludedName` как скалярный параметр
   с подписью и значением по умолчанию. Необъявленные параметры при применении
   автоматически добавляются; тип и свойства можно уточнить в редакторе параметров.
   Для ссылочного параметра выбрать тип «Сущность» и её класс.
4. Нажать **«Применить и закрыть»**. Колонки берутся из проверенного результата
   запроса. Для чисел доступны SUM/AVG/MIN/MAX, отдельно — количество записей.
5. Настроить подписи, порядок, группы, итоги, отборы и оформление. Значения
   параметров текущего запуска вводятся над кнопкой **«Сформировать»**.
6. Сформировать отчёт, проверить preview и скачать PDF или XLSX.
   **«Параметры запроса…»** позволяет вернуться к декларациям параметров.

Это JPQL/HQL и визуальные определения, которые уже поддерживает UDR. Конструктор,
каталог сущностей, JOIN, условия и расширения языка не реализуются вторым движком.
Текущий guard UDR требует скалярные проекции: выбирать `r.name as recipient`,
а не целую сущность `r`. Это не препятствует параметрам-сущностям.
Период связывается как `:periodFrom` и `:periodTo`.

## Модель и выполнение

`UniDrDefinition.query` — необязательный immutable `UniDrQuerySource`: вид
источника UDR, JPQL, визуальный JSON и декларации параметров. Старые определения
JSON v1 без этого поля и старые Java-конструкторы работают как прежде. Временный
`ReportTemplate` служит адаптером редакторов UDR и не сохраняется в БД.

`ReportQueryAssemblyService.describe` компилирует тот же источник и проверяет
его через существующий guard, без разрешения значений параметров и выполнения
источника. Схема берётся с сервера, а не из клиентских колонок.
При запуске сборщик UDR повторно проверяет запрос и разрешает параметры через
существующий resolver и canonical lookup. В worker передаются scalar/ID snapshots,
а не живые JPA-сущности. Чтение выполняется в отдельной read-only транзакции с
действующими RLS/C5, владельцем, timeout и лимитом UniDR.

Числа нормализуются в BigDecimal, даты — в LocalDate, остальные скалярные
значения — в текст. Дополнительные отборы UniDR и порядок групп применяются к
**полному** ограниченному результату запроса. Если источник превышает лимит
(максимум 5000 строк), запуск завершается ошибкой до этих отборов; частичные
итоги не публикуются. Для большого исходного набора условия задаются в WHERE.
Рендер и экспорты используют один detached dataset и не выполняют SQL.

Повторное применение запроса сохраняет настройки совместимых полей. Настройки
исчезнувших полей удаляются с сообщением; новые поля доступны для выбора.
Отмена редактора работает с частной копией. Ошибка применения оставляет диалог
открытым. Смена источника, настройки и параметров инвалидирует результат и ссылки
скачивания штатным механизмом U4.

## Общие исправления UDR

- `ReportQueryGuard.parameterNamesOf` и анализ редактора учитывают реальные
  имена границ PERIOD (`From`/`To`). Ранее проверка отклоняла корректный период.
- `ReportQueryDialog` показывает ошибку callback применения и остаётся открытым.
- В переиспользуемом `RegisterSliceQueryDialog` исправлено обращение к текущему
  nongeneric контракту `IdentifiableEntity`.
- `UniDrQueryUiSupport` внесён в реестр `report-form-seam.txt`: выбор сущностей
  использует существующий `SelectionFormAssembler`.
- `ReportParamForm.setChangeListener` сообщает об изменениях scalar/period,
  выборе сущности и добавлении/удалении строк списка. UniDR снимает старые
  ссылки скачивания и при выборе через модальное окно. Удаление строки
  ENTITY_LIST также удаляет её контейнер, а не только внутреннее поле.
