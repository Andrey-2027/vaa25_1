# AF5.5: новый API карточки и пилот Workshop

Дата: 06.11.2026. Реализация и технические сценарии К3 выполнены.
Визуальная проверка агентом проведена; подтверждение приёмки владельцем
отдельно не заявляется. Полный прогон не выполнялся по указанию владельца.

## Решения владельца и К1

- Подход layout()/adjust() принят; К1 явно закрыта владельцем.
- Отдельный показ двум-трём прикладникам заменён этим решением, не заявляется выполненным.
- Основной Workshop: Код / Наименование / Филиал. Демонстрационные ID, подсказка
  и «Наименование1» убраны из пилота. Правило «Фин» только в тестовом варианте.
- Для стартовой проверки разрешён пустой экземпляр ItemForm, без редакторов,
  таблиц и других дочерних компонентов.
- Обновлены П4 правил и §0 прежнего плана; исключение @Lookup.searchFields
  в П5 уже было удалено в AF1.2.

## Реализация

Добавлены FormFor, Layout, FormAdjust, FormBehavior и внутренний ElementNode.
Словарь замкнут; рендер остаётся в switch по LayoutNode.
Описание поддерживает поля, вывод, ленивые custom-фабрики, панели, вкладки,
секции, остальные поля/исключения, правки состава и расположения, подписи,
видимость, ширины, readOnly и локальный вариант выбора.

Регистрация FormFor сосуществует с ItemFormCustomization. Дубликаты, неверная
привязка generic/entity и цепочка классов длиннее двух уровней отклоняются.
Стартовый экземпляр только описывает форму и объявления обработчиков: имена,
пути, ссылки, идентификаторы, перемещения, секции и варианты выбора проверяются
до открытия. Невыведенное обязательное поле даёт адресное предупреждение;
явное удаление и скрытое привязанное поле считаются сознательным решением.

Новый ItemForm без аргументов остаётся пустым до FormResolver. Порядок открытия:
экземпляр → layout/remaining/adjust → единичный рендер → behavior → старые
кастомайзеры → секции → заполнение/режим чтения в координаторе.
Компоненты и состояние не кэшируются. Старые конструкторы и сложные формы сохранены.

onChange подавлен при загрузке и применении результата записи. onLoaded
вызывается после открытия/создания и записи; aggregate-адаптер группирует шапку,
строки и commitSnapshot, чтобы обработчик видел весь применённый результат.

WorkshopItemForm переведён на FormFor; его прежний WorkshopFormConfig удалён,
чтобы не оставлять двойную регистрацию. Остальные производственные формы
не мигрировались. «Фин» находится только в WorkshopItemFormTest.FinForm/test-fin.

Описание API: [карточка и компоновка](../../forms/item-form-layout.md).
