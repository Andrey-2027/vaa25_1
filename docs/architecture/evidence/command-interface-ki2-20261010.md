# КИ-2: хранение профилей и назначения пользователям

- Дата: 2026-10-10.
- План: [пилот командного интерфейса](../command-interface-pilot-plan.md).
- Предыдущий этап: [КИ-1](command-interface-ki1-20261010.md).
- Объём: backend профилей и назначений; интеграция меню и редактор ещё не входят.
- Результат: КИ-2 выполнен; весь пользовательский пилот ещё не готов.

## Реализация и границы

`platform-navigation` владеет тремя JPA-таблицами: `navigation_profile`,
`navigation_override`, `navigation_assignment`. Они наследуют `BaseEntity`,
не имеют `@EntityMetadata` и классифицируются существующим descriptor-каталогом
как `INTERNAL_STORE` без canonical read/write capabilities. В приложении нет
новых JPA-полей или связей `User`; `user_key` хранит непрозрачный неизменяемый
ID, а не логин. В текущем адаптере это строковое представление `User.id`.
FK связывают только собственные таблицы навигации.

Публичные интерфейсы `NavigationAdministrationService` и `NavigationProfileReader`
отделены от внутренних реализаций, репозиториев и сущностей. Результаты —
неизменяемые detached-записи `NavigationProfile` и `UserOption`.
В семантический signature baseline не входят внутренние классы хранилища.

Административный сервис предоставляет создание/список/чтение/переименование
профилей, замену состава с ожидаемой версией, сброс, назначение/переназначение,
снятие и чтение назначения для редактора, а также ограниченный поиск пользователей.
Удаление профилей и назначения по ролям не добавлены.

Каждый административный метод сначала проверяет `NavigationAdministrationAccess`,
включая чтение и прямые Java-вызовы. Разрешающей реализации по умолчанию нет.
Прикладная конфигурация реализует правило аутентифицированного `ROLE_ADMIN`;
anonymous не получает доступ даже при такой authority в тестовом токене.
`NavigationUserDirectory` использует canonical lookup/detail для поиска и
проверки существования пользователя; предел поиска 1..50. Репозиторий приложения
используется только для перевода текущего аутентифицированного логина в `User.id`.
Неизвестная или отсутствующая аутентификация не подменяется системным пользователем.

Имена профилей непустые, обрезаются по краям и уникальны без учёта регистра;
максимум 120 символов. Уникальные ограничения защищают имя, пару профиль/цель
и единственное назначение на пользователя. Цели и ключи пользователей ограничены
190 символами; слишком длинная цель отвергается при включённом запуске каталога.

Изменение профиля блокирует его строку, проверяет ожидаемую `@Version`, затем
изменяет внутренний счётчик агрегата. Поэтому запись только переопределений
и даже пустой сброс увеличивают версию. Второе конкурентное сохранение получает
`NavigationConflictException`; чужой состав не перезаписывается. Операции используют
транзакции владельца и участвуют в откате внешней транзакции. Конкурирующие изменения
одного назначения также могут вернуть конфликт, после которого требуется перечитать
состояние. Generic CRUD и новые C5 grants для внутренних таблиц не вводились.

DEFAULT не сохраняется. Обычное сохранение заменяет только известные цели,
сохраняет ранее записанные устаревшие ключи и не позволяет добавить/изменить
неизвестную цель. Полный сброс удаляет и устаревшие ключи, сохраняя назначения.
Чтение текущего профиля ограничено текущим пользователем, не требует администратора
и не имеет общего кэша. Новые read-транзакции используют repeatable-read;
внешняя транзакция сохраняет свою изоляцию. Отсутствие назначения возвращает
пустой Optional; ошибка БД передаётся вызывающему коду.

## Включение и поставка

`NavigationAutoConfiguration` зарегистрирована в собственном
`AutoConfiguration.imports` и активируется только при `platform.navigation.enabled=true`.
По умолчанию флаг выключен. В выключенном приложении не регистрируются новые
сервисы, security/user-адаптеры, репозитории и JPA-типы; таблицы не создаются.
Включение без обязательных адаптеров является ошибкой запуска.
Общие starters не изменялись.

Additive DDL поставляется в
`platform-navigation/src/main/resources/db/navigation-postgresql.sql`.
Его применяют один раз к подготовленной пилотной БД, затем включают флаг и
`spring.jpa.hibernate.ddl-auto=validate`. Скрипт не изменяет прежние таблицы
и не вводит migration framework. Режим главного приложения оставлен выключенным;
обычная рабочая БД не изменялась.

Прямое ребро `platform-navigation -> platform-persistence` добавлено в Maven
и локальный манифест. Роли всех 29 типов, включая вложенные, зафиксированы
в module-owned реестре. Fingerprint: 35 файлов, `gitvaa-source-tree-sha256-v2`.
API baseline обновлялся только для `platform-navigation` и повторно сверялся
без режима записи. Проверенный модуль установлен в локальный Maven-репозиторий.

## Проверки и повторение

| Проверка | Результат |
| --- | --- |
| Каталог, resolver и композиция КИ-1 с новой поставкой | 30 успешных |
| `NavigationPersistenceTest` | 10 успешных: JPA/H2, доступ ко всем методам, версии, конкурентная запись, откат, stale keys, constraints, экспозиция, выключение и обязательные адаптеры, ошибка чтения |
| `NavigationPostgresqlTest` | 1 успешная: DDL + `validate`, реальное сохранение, закрытие/повторное создание контекста, назначение и переопределения после перезапуска, конфликт версии и сброс |
| Прикладной contributor и `ApplicationNavigationSecurityTest` | 4 успешных: реальная metadata-полнота, `ROLE_ADMIN`, anonymous, стабильный ID при смене логина, canonical lookup/detail и лимит |
| Полное приложение, enabled/disabled smoke | 2 успешных с `rls.write-boundary.enforced=true`; операции владельца работают, выключение исключает сущности/сервисы/таблицы |
| Signature baseline нового модуля | 4 успешных, проверка без перезаписи |
| `WorkspaceManifestTest`: порядок, Maven-рёбра и владелец координат | 3 успешных |
| `PlatformArchitectureTest` | 3 успешных: bytecode-границы платформы, приложения и metadata |

Итого **57 успешных проверок** затронутого контура; повторные прогоны не суммируются.
В независимой сборке 40 тестов прошли, 1 PostgreSQL-тест ожидаемо пропущен;
отдельный PG-прогон затем выполнил его успешно на итоговых исходниках.

Повторный общий `PlatformPublicSurfaceTest` дал прежние 5 успешных и 5
неуспешных проверок: wildcard/FQN-обращения соседнего UniDR, отсутствующие
reviewed-роли отчётных типов/`RlsContext`, ссылка на legacy `EntityRef` и общий
дрейф замеров. Навигационные типы в диагностике нарушений отсутствуют.
Фактический общий счётчик прикладных исходников — 233, документированный — 199;
в документ внесена только дельта этого этапа. Общая сборка репозитория не
объявляется полностью зелёной. Fingerprints остальных изменённых модулей
и signature baseline прочих артефактов в этом прогоне не перезаписывались.

Full-application smoke исключает классы из `target/test-classes` из component scan
тестовым `TypeExcludeFilter`: иначе соседние самостоятельные UniDR smoke-приложения
объявляют несколько одноимённых security-бинов. Production scan не менялся.
Стандартный Spring Boot test listener потребовал разрешённый Java attach IPC;
финальный прогон выполнен вне ограниченного sandbox. Сами smoke-тесты используют H2.

Команды из корня при подготовленных прежних локальных зависимостях и Java 21:

```powershell
mvn -o -f platform-navigation/pom.xml clean install
mvn -o test '-Dtest=ApplicationNavigationConfigurationTest,ApplicationNavigationSecurityTest,NavigationApplicationSmokeTest,NavigationDisabledApplicationSmokeTest,PlatformApiBaselineTest' '-Dplatform.api.baseline.artifact=platform-navigation'
& .\scripts\test-navigation-postgresql.ps1
& .\scripts\diagnose-source-fingerprint.ps1 -ProjectId platform-navigation -Cultures InvariantCulture
```

PostgreSQL-скрипт берёт локальное подключение из `config/application-local.properties`,
не печатает пароль, создаёт только отдельную БД `navigation_ki2_<guid>`, применяет
поставляемый DDL, выполняет тест и удаляет созданную БД. Существующая БД не является
целью записи. Обычный Maven-прогон пропускает PG-тест без его окружения; отдельный
PostgreSQL-прогон выполнен с реальным локальным PostgreSQL 17.10.

КИ-3 должен подключить текущего пользователя, сохранённый профиль и `RlsReadGate`
к одному снимку бокового меню и плиток. КИ-4 добавит административный экран.
Сейчас действующее меню не меняется; браузерная приёмка профилей ещё не проводилась.
