# AF4.3 — патчер и предупреждение о явном составе

Дата: 07.11.2026, Europe/Moscow. Основание: основной план AF4.3/Р17/Р19,
рабочий план §8 и пакет 1 (§1.1). Полный прогон не выполнялся.

## Результат

JavaEntityPatcher добавляет поле и его аксессоры только в Java-файл сущности.
Промежуточный отказ AF4.2 снят. Файлы конфигураций форм не меняются.
Для внешних объявлений не создаются listColumns/selectColumns на сущности.

- AUTO публикует поле через @FieldMetadata/grid с сохранением запрошенных
  признаков публикации. Учитываются основной состав и именованные AUTO-варианты.
- EXPLICIT остаётся прежним, в том числе при совпадении с текущим AUTO.
  Поле появляется в сущности и карточке согласно form-признаку, а состав колонок
  такой формы не расширяется. План сообщает об этом отдельным WARNING.
- Новые список и выбор независимы. Две AUTO-формы используют общий grid:
  несовместимые запросы «в списке да, в выборе нет» дают адресный отказ,
  поскольку без изменения объявления формы их нельзя представить.
- Старые массивы продолжают расширяться по прежним правилам; байтовый паритет
  со старыми рецептами генератора сохранён.
- Переходный случай: внешний список EXPLICIT + старый listColumns на сущности,
  который ещё питает выбор. Патчер может расширить старый массив для выбора;
  внешний список остаётся неизменным. Если публикация в выборе не запрошена,
  старый массив остаётся побайтно прежним.

Пример предупреждения:

«В форме «t.Forms» (список) явный состав, реквизит «address» не добавлен.»

Указаны класс конфигурации, список/выбор и именованный вариант, если он есть.
Код — FORM_EXPLICIT_FIELD_NOT_ADDED, severity — WARNING, target содержит
идентичность поля и applications.list/selection. Текст и структурированные
параметры входят в сохраняемый ModificationPlan и его идентификатор.
CLI и EntityModifyView показывают читаемый текст вместо внутреннего enum.
Изменение подписи без добавления реквизита такого предупреждения не создаёт.

## Данные и актуальность плана

ExistingEntity.formDeclarations хранит все прочитанные объявления через новый
нейтральный ExistingFormDeclaration(kind, variant, columns). Прежние сигнатуры
конструкторов ExistingEntity сохранены, включая сигнатуру AF4.2 с двумя
основными составами. Все структуры неизменяемы; зависимости от Vaadin в core/source
не добавлены. Основные listColumns/selectionColumns сохраняют прежние значения.

Все прочитанные конфигурации, включая файлы только с именованными вариантами,
попадают в ModificationPlan.dependencyHashes. Их изменение после планирования
даёт CONFLICT_DEPENDENCY_CHANGED до записи сущности. Файл сущности проверяется
прежним baseSha256; сохранение/чтение плана с новыми предупреждениями проверено.

План по-прежнему изменяет один Java-файл сущности: это не команда миграции
AF4.4, которая должна переносить настройки между файлами. Здесь
конфигурации — только прочитанные зависимости. ModificationApply не менялся.

FormColumnPatcherTest проверяет основную матрицу AUTO/EXPLICIT, независимость
ролей, одинаковый с AUTO явный состав, скрытую публикацию, именованные варианты,
конфликт несовместимой AUTO-публикации, старые массивы и переходный fallback.
Проверяется, что конфигурации не меняются ни при планировании, ни после настоящего
применения, предупреждения переживают PlanDirectory round-trip, повторное
планирование детерминировано, изменение файла вариантов блокирует применение.
EntityModifyCliTest дополнительно проверяет русский текст предупреждения и
наличие предупреждения в сохранённом плане.

PatchedFormColumnsPlatformParityTest патчит и компилирует семь сущностей вместе
с неизменными конфигурациями, затем использует настоящий Spring
FormColumnDeclarationsCollector/MetadataResolver. Покрыты AUTO/AUTO,
EXPLICIT/EXPLICIT, два смешанных режима, старые массивы, переходный fallback
и именованный AUTO при явных основных составах. Окончательные колонки
сравниваются с заранее заданными ожиданиями и результатом читателя.

EntityModificationTest проверяет новый текст в компоненте редактора,
наличие патча поля и отсутствие записи до применения. Прежние сценарии
редактора, PatchedModelParityTest и PatcherGeneratorParityTest прошли.
Снимок П.2 совпал без перезаписи. Тесты записи запускались с правом работы
во временных каталогах; источник моделей приложения не заменялся.
Для целевого запуска приложения использован явный Mockito -javaagent.
