# AF5.6 — ReceivingDocument (08.11.2026)

## Перенос

По поручению владельца удалена ReceivingDocumentFormConfig. Её фабрика отбирала
те же пять реквизитов, которые уже содержит метадата карточки; особых обработчиков
или редакторов не было. FormResolver теперь использует штатную автоформу ItemForm:
дерево с remainingFields, порядок journal, number, date, receivingWorkshop,
transferringWorkshop. Новый класс карточки не нужен. Секция ReceivingDocumentItem
«Позиции» подключается прежним TableSectionFactory.

Объявления @ListColumns/@SelectionColumns перенесены без изменения значений и
режимов в существующую ReceivingDocumentListFormConfig с @FormConfigurationFor.
Панель журнала, периода и цеха-приёмщика, свойства колонок секции и модель не
менялись. EXPLICIT выбора, закреплённый в AF4.5, сохранён.

Безопасный локальный предпросмотр Explorer ранее вызывал удаляемую фабрику.
Теперь он строит ту же автоформу с локальными FieldFactory/строками. Разрешён
только подтверждённый платформенный ITEM/default без прикладной регистрации;
произвольная фабрика по-прежнему не вызывается. Карточка в фактах Explorer
показывается как платформенная автогенерация, без ссылки на удалённый конфиг.
Это адаптация существующего предпросмотра, а не реализация AF5.7.

## Проверки

Все 123 целевые проверки прошли без ошибок и пропусков. Итоговый журнал:
target/af56-receiving/regression-final.log. Новый ReceivingDocumentAutoformIT
проверяет пять обязательных полей в прежнем порядке, одну секцию, отсутствие
регистрации ITEM-фабрики, прежние составы списка/выбора, начальное заполнение
журнала, обязательность и dirty, реальную запись через штатный FormSaveHandler и
повторное чтение шапки с позицией, id и номером строки. Проверен clean baseline
после сохранения и повторного открытия. Номер остаётся генерируемым: пустое значение
до записи допустимо, сервер назначает РН-2026-…, форма получает назначенный номер.

Проверки предпросмотра охватывают пустой и заполненный режимы, локальный поиск,
запрет операций с данными, повторное открытие и отсутствие ссылок на удалённую
регистрацию. Снимок П.2 совпал без перезаписи; отдельно прошли проверки списка с
панелью отборов, существующих правил записи накладной, сборки всех карточек,
паритета дерева и плоского входа, читателя исходников, runtime-каталога адресов
и границы прикладного чтения.

Метаданный unit-тест происхождения колонок теперь явно передаёт обычному
MetadataResolver аннотации действующей конфигурации: без Spring-коллектора они
сами не подключаются. Старое ожидание наследуемого выбора заменено на EXPLICIT,
согласованный ещё в AF4.5. Рабочая логика платформы для этого не менялась.

Полный прогон, frontend и C/D harness не запускались по действующему указанию
владельца. Визуальная приёмка К4 не объявляется: состав и компоненты сохраняются,
проверки текущего шага — программные.

## Границы

Изменены только прикладная конфигурация, предпросмотр и соответствующие тесты.
Платформенные исходники и отпечатки не менялись. Используется проверенный артефакт
platform-vaadin предыдущего шага PrdSpec (изолированная сборка без параллельных
изменений команд). Параллельные изменения команд, API и проектировщика сохраняются
в рабочем дереве и не включаются в коммиты этого шага. Ранее зафиксированные
расхождения общего bootstrap и статических адресов здесь не исправляются.

Текущий согласованный объём переноса пилотов AF5.6 после этого шага завершён;
миграция AccountingObjectCorrection остаётся явно отложенной. Следующий шаг —
подготовка приёмки К4 с согласованием её границы для старой корректировки;
К4 автоматически не закрывается. Отбор дополнительных единиц AF5.8 ждёт О5.
