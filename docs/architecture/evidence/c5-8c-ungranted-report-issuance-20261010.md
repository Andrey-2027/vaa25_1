# C5.8c: «определение зарегистрировано, грантов нет» и первичная выдача — 2026-10-10

- План: [C5.4–C5.10](../c5-operation-permissions-plan.md), пакет C5.8 («Администратор и первичная
  выдача»), остаток после [C5.8](c5-8-named-operation-issuance-20261008.md) и
  [C5.8b](c5-8b-operation-effective-rights-20261009.md): отчёт «определение зарегистрировано,
  грантов нет» и первичная выдача для обычной базы.
- Решения: [ADR-0017](../decisions/ADR-0017-c5-single-operation-authority.md) §3 (носитель права —
  глобальная строка `access_grant`; `'*'` и value-scoped строки операцию не решают), §5 (реестр
  определений — единственный способ признать ключ), §10 (безопасный текст отказа);
  [ADR-0019](../decisions/ADR-0019-owner-named-row-operation.md) (именованные операции владельцев
  выдаются точечно).
- Предшественники: [c5-4-inputs-20261006.md](c5-4-inputs-20261006.md) — риск lockout обычной базы
  (запись типов без измерений закроется «включая `admin`»); [c5-7b](c5-7b-e12b-action-operation-gate-20261009.md) —
  предсказание видно в UI: явные операционные строки выдаёт только пилотный профиль.
- Метод: метод админ-сервиса + секция экрана + условный стартер первичной выдачи; unit-тест
  семантики отчёта и IT на реальном JPA; прогоны среза и соседних наборов.

## 1. Что было не так

1. **Закрытое определение было не видно.** Ключ, объявленный платформой и не выданный никому,
   обнаруживал только тот, кто сам догадается открыть его на экране выдачи. Новый тип с canonical
   write handle оказывался молча закрыт **включая для администратора** — ни одна строка его не
   открывает, а спросить «кому вообще выдано» было негде.
2. **Обычная база оставалась запертой.** По C5.4 в ней операции типов без измерений держались на
   отсутствии проверки: после включения enforcement их запись отказывает и `admin`. Пилот выдал
   себе строки фикстурой, обычная база — нет; выдать вручную два десятка ключей (read-ключи и
   операции — разные строки, ADR-0017 §3) экран не помогал.
3. **Выдача не была связана с определениями.** Любой «пакетный» способ выдать права обязан
   строиться из тех же реестров, что спрашивает решение, иначе выданная строка разойдётся с тем,
   что решит сервер.

## 2. Что сделано

| Место | Было | Стало |
| --- | --- | --- |
| [`AccessGrantAdminService`](../../../src/main/java/org/ip/service/AccessGrantAdminService.java) | — | `ungrantedDefinitions()` + `UngrantedDefinition`: определения (операции типов, именованные операции, read-ключи, API), у которых нет ни одной **решающей** строки ни у одного субъекта. Решающая строка операции — глобальная строка с флагом объявленной операции; read-ключа — глобальная строка с флагом чтения. `'*'` и value-scoped строки в счёт не идут: они не авторизуют ни операцию, ни C5 read. Отчёт считается по всем субъектам: «у выбранного нет» — не признак закрытости вообще |
| [`operationGrantFlags`](../../../src/main/java/org/ip/service/AccessGrantAdminService.java) | формула флагов в `expressibleFlags` | одна формула и для показа, и для первичной выдачи: CREATE/UPDATE/EXECUTE → «изменение», DELETE → «удаление», чтение — только если объявлено. Записанная строка не может говорить не то, что решает сервер |
| [`AdminView`](../../../src/main/java/org/ip/views/admin/AdminView.java) | — | секция «Определения без выданных грантов» с подсказкой «никому не выдано — включая администратора»; обновляется после каждого сохранения, поэтому выданное право тут же исчезает из отчёта. Пустой отчёт скрывается |
| [`InitialGrantIssuance`](../../../src/main/java/org/ip/config/InitialGrantIssuance.java) | — | условный стартер первичной выдачи: `app.security-baseline.enabled=true` (по умолчанию **false** — право выдаёт администратор), `app.security-baseline.roles=ADMIN`. Идемпотентно добавляет роли недостающие read-ключи и операции сущностей; существующие строки не дублирует и не переписывает; определения `ACTION:`/`REST:` не трогает — это точечные права владельца и канала (C5.8). `@Profile("!prod")` |

Пилотная фикстура не менялась: она по-прежнему выдаёт свои строки сама и остаётся проверкой того
же правила на живом сценарии. Первичная выдача — тот же путь для обычной базы, включённый
оператором, а не «разрешить всё»: выдача перечисляет ровно объявленные определения.

Всего 55 тестов перечисленных наборов, 0 отказов. Команды: `mvn -o test-compile`, затем
`mvn -o surefire:test -Dtest='...'` (наборы из таблицы).

**Ограничение прогона.** В текущем дереве любой общий контекст приложения не поднимается из-за
**чужих незавершённых** смок-конфигураций `org.ip.views.unidr.smoke.*` (тестовые исходники,
`@SpringBootConfiguration` в сканируемом пакете тестов: конфликт bean `security` и два
`RlsCurrentUser`). Срез проверен без их **скомпилированных** классов на тестовом classpath
(`target/test-classes/org/ip/views/unidr/smoke/*.class` удалены перед `surefire:test`, исходники
не тронуты); после их починки ограничение снимается без правок среза.

**Замер поверхности не переписан намеренно.** `app-source-files` дорос бы до 197 от одного файла
этого среза, но живой счёт — 227: остальное дают чужие untracked источники UNIDR. Перезапись замера
(`-Dplatform.measurements.write=true`) впитала бы чужую незавершённую работу и их поверхностные
отказы (wildcard-импорты, unreviewed типы) — тот же случай, что манифест в C5.7b. Документ
обновляется, когда чужие изменения приняты; тогда `PlatformPublicSurfaceTest` снова станет
источником истины без правок этого среза.

## 4. Остаток

- **C5.8: самоповышение (П13)** — отдельные определения назначения ролей и смены пароля,
  проверяемые и на прямом вызове сервиса; не сделано.
- **Включение первичной выдачи в обычной базе** — операторское: `app.security-baseline.enabled=true`
  и `app.security-baseline.roles`; по умолчанию выдача выключена, право выдаёт администратор.
  Отчёт показывает, что осталось невыданным, до и после.
- **UI не кликался**: секция отчёта скомпилирована и покрыта сервисными проверками, но не живым
  браузером; это тот же класс непроверенного, что и в C5.7b.
- Полная матрица П01–П14 и PostgreSQL-шаг — C5.9, как и прежде.
