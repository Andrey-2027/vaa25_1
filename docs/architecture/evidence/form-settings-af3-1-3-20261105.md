Статус: реализовано. Полный прогон не выполнялся по указанию владельца.

## Объявление колонок

Аннотации находятся в `platform-contracts`, класс конфигурации — обычный Spring-бин:

```java
@Component
@FormConfigurationFor(Workshop.class)
@ListColumns({"code", "name", "branch"})
@ListColumns(value = {"code", "name"}, variant = "compact")
@SelectionColumns({"code", "name"})
public class WorkshopFormConfig {
}
```

Конфигурация может одновременно реализовывать существующие `*FormCustomization`.
Создавать подклассы ListForm/SelectionForm ради колонок не требуется. `@Bean` должен
объявлять конкретный тип конфигурации: скрытый за Object/интерфейсом аннотированный
тип отклоняется при старте, а не теряет объявления молча. Обычные проксируемые
`@Configuration` поддерживаются. Статическая привязка проверяется на соответствие
`entityClass()` у конфигураций списка и выбора.

`FormColumnDeclarationsCollector` собирает объявления из типов бинов без создания
конфигураций и вызова configure. Все варианты проверяются до фиксации, включая
неоткрытые варианты. Пара (сущность, вид формы, вариант) уникальна; при дубле ошибка
называет оба источника. Неизвестный путь останавливает старт. Замороженный реестр
`FormColumnDeclarations` не зависит от Vaadin и подключается к MetadataResolver
до первого разрешения метаданных. Поздняя установка непустого реестра запрещена.

Default читается через `getListColumnPaths`/`getSelectColumnPaths`: новая аннотация
конфигурации → соответствующий старый атрибут EntityMetadata → автоматический состав.
Старое правило selectColumns → legacy listColumns сохранено для совместимости;
новый ListColumns сам по себе состав выбора не задаёт. После удаления старых
атрибутов отсутствие нового объявления означает автоматический состав. Пустой
массив в новой аннотации тоже означает автоматический состав, а не пустой грид.
Без UI-коллектора остаются старые атрибуты и автоматический состав.

Именованные варианты разрешаются отдельно, общий объект метаданных не меняется.
ListForm получает готовые колонки до сборки грида; сброс сохраняет состав текущего
варианта. Сохранённые виды продолжают применяться существующим механизмом.
Именованный вариант без фабрики автоматически собирается платформой; неизвестный
вариант по-прежнему отклоняется. Колонки custom factory остаются ответственностью
самой фабрики, как до AF3.

## Уточнение владельца

Вместо исправления позднего `SelectionFormVariants.addDefaultColumns` метод удалён.
Вызовов в приложении и тестах не было. Default-колонки задаются ранними аннотациями.
`addColumns(null/blank, ...)` запрещён в обоих UI-коллекторах. Именованные
`addColumns(variant, ...)` сохранены; для списка добавлен симметричный API.
Объявление одного набора одновременно аннотацией и через configure — дублирование,
которое останавливает старт с обоими источниками.

## Совместимость и предупреждения

EntityMetadata.listColumns/selectColumns и GridColumn помечены Deprecated без
forRemoval. Массовый перенос модели и генератор остаются AF4. При старом атрибуте
проверка согласованности выдаёт LEGACY_FORM_COLUMNS с адресом сущности и подсказкой
класса конфигурации. При новом и старом объявлении одного default-набора —
DUPLICATE_FORM_COLUMN_SOURCE: новая конфигурация имеет приоритет, оба источника
названы. Это проверено модульным тестом; в модели приложения новых объявлений пока нет.
