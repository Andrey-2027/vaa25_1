# AF5.6 — карточка PrdSpec (08.11.2026)

## Объём

По поручению владельца завершён перенос PrdSpec из остатка AF5.6. Миграция
AccountingObjectCorrection остаётся отложенной; ReceivingDocument в этот шаг
не входит. Полный прогон запрещён владельцем и не выполнялся.

## Изменения

- PrdSpecItemForm объявлен через @FormFor и remainingFields. Варианты full и
  materials-only — отдельные подклассы; порядок пяти полей шапки и состав секций
  сохранены: default/full — материалы и операции, materials-only — материалы.
- READ_ONLY_SECTIONS — типизированный параметр формы. Список содержит только
  PrdSpecMtr/PrdSpecOper, копируется на открытие и применяется в behavior() до
  подключения секций. Параметр меняет доступность, а не состав формы.
- Платформенный FormParameter/FormParameters проверяет объявленные ключи, тип
  значения и элементы списка. Фабрика @FormFor связывает параметры до создания
  редакторов. При стартовой проверке behavior получает значения по умолчанию.
  Неизвестный бизнес-параметр отклоняется; служебные данные координатора отделены.
  Старый Map с readOnlySections поддерживается с той же проверкой. Старые фабрики
  с FormContext сохраняют прежний вход совместимости.
- Ограничение номенклатуры шапки перенесено из фабрики в adjust/setSelectionFilter:
  Узел, ДСЕ, Нормали, ПКИ, Прочее. Действует в автокомплите и диалоге.
  Зависимость чтения nomenclature для этого отбора выведена через AF5.8/AF5.6.
- PrdSpecFormConfig сохраняет только статические @SelectionColumns. Фабрики и
  зависимость от SelectionFormAssembler удалены.
- Неиспользуемый список contextual и PrdSpecByJournalView удалены. Панель выбора
  журнала стандартного списка и действие «Только материалы» сохранены.
  Публичный эталон адресов меняется только удалением LIST-варианта contextual;
  ITEM-варианты сохраняются. Проверка исходников адресов научилась учитывать
  литеральные варианты @FormFor наряду со старыми фабриками.

API и пример вызова: [параметры формы](../../forms/form-parameters.md).

## Проверки

Платформа: 30 целевых тестов прошли (параметры, описание, связанные поля,
зависимости чтения, регистрация описаний). Журнал:
target/af56-prdspec/platform-tests.log.

Итог приложения: 154 целевых теста прошли без ошибок и пропусков; всего с
платформой — 184. Журнал: target/af56-prdspec/regression-final.log. Набор включает
составы секций, независимость открытий и ошибочные параметры, реальный SQL обоих
каналов выбора, запись/повторное чтение шапки с материалами, required/dirty,
загрузку и saved state, варианты строк, отмену/скрытые секции, сборку всех карточек,
снимок П.2, снимок потребностей чтения, источники и runtime-каталог адресов.
Реальная запись через штатный FormSaveHandler и повторное чтение сохраняют
изменённую шапку, две строки материалов и одну операцию; clean baseline обновляется.

Первый набор приложения: 69 проверок, 67 успешны. Исправлено ошибочное ожидание
типа исключения в новом тесте удаления contextual (штатный контракт —
IllegalStateException). Другой отказ — прежний общий забор статических адресов:
в параллельной незавершённой работе появился /command-bar-demo, отсутствующий
в общем эталоне. Это изменение не включено в данный шаг и не маскируется
перезаписью эталона. Проверка составов вариантов PrdSpec прошла.

П.2 совпал без перезаписи. Отдельный снимок потребностей чтения расширен тремя
вариантами шапки PrdSpec; прежние записи строк и базовых планов сохранены.
Скаляр typeNom не требует связи LOOKUP: после нормализации список дополнительных
связей поля пуст, а DETAIL получает nomenclature для чтения параметров выбора.
Визуальная приёмка К4 этим отчётом не объявляется. Нового макета нет: перенос
сохраняет компоненты, порядок полей и видимые секции.

## Изоляция и ограничения

В общем рабочем дереве остаются параллельные изменения API команд списка и движка
проектирования сущностей. Для этого шага platform-vaadin собран из отдельной копии
HEAD после AF5.8 с наложением только шести файлов данного шага. Целевые тесты
приложения используют установленный изолированный артефакт. Параллельные правки
не входят в коммиты, артефакт и эталон отпечатка данного шага.

Отпечаток исходного состава platform-vaadin: 268 файлов,
`e33ad00eced00d5b84a308ff9462c921d93712f3bef332d358aab3fdebf96fa8`.
Он сохраняет фактические окончания строк исходного дерева; обратная проверка
воспроизводит эталон AF5.8. Строгая проверка общего дерева остановилась на
параллельных правках platform-vaadin (268 → 274 файла). Диагностический проход
с AllowSourceDrift завершён, кроме него виден только прежний drift
platform-report-vaadin (33 → 34 файла); чужой эталон не обновлялся.

После этого шага в AF5.6 остаётся ReceivingDocument; корректировка отложена.
О5 дополнительных единиц остаётся отдельным остатком AF5.8; К4 ещё не закрыт.
