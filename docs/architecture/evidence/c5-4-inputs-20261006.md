| RestCheck | `REST:nomenclature:v1:LIST`, `:DETAIL` | — | t | f | f |

Пользователей 4, ролей 3. `ENTITY:ReceivingDocument` — короткий ключ, то есть
действующий CHECK_ONLY-гейт выдан явно только для одного типа.

### 2.3. Что из этого следует

1. В пилоте операции всех восьми типов держатся **только** строкой `'*'`: для двух
   документов и записи регистра — через CHECK_ONLY-гейт, для `Nomenclature`,
   `UnitOfMeasurement`, `AccountingType`, `NomenclaturePrice` — вообще без гейта
   (тип без измерений, запись fail-open).
2. Строки `ENTITY:<FQN>` в пилоте — read-ключи C5 со «случайными» `can_update`/
   `can_delete`. По ADR-0017 они остаются read-ключами, их write-флаги инертны (так же,
   как сегодня), а операционные гранты — это отдельные строки с коротким ключом.
3. `DBVaa25` живёт без wildcard, поэтому развязка `'*'` там ничего не отнимает. Но
   включение C5-операций закроет запись для типов без измерений (`Nomenclature`, `Role`,
   `User`, `AttributeType`, …) **включая `admin`** — это и есть основной риск lockout,
   и он количественно мал: 4 пользователя, 3 роли.

## 3. Меняется ли поведение пилота при включении

| Что | Пилот (`accounting_object_pilot_local_v2`) | `DBVaa25` |
| --- | --- | --- |
| Чтение 8 типов | Сохраняется: есть точные FQN-строки. C5 read и сегодня не принимает `'*'` | Без изменений: read-строки точечные |
| Создание/изменение/удаление документов учёта | **Закрывается**: гейт держался на `'*'` | Без изменений для `ReceivingDocument`: короткий ключ выдан явно |
| Запись регистра объекта учёта | **Закрывается**: короткого ключа нет | — |
| Запись `Nomenclature`, `UnitOfMeasurement`, `AccountingType`, `NomenclaturePrice` | **Закрывается**: сегодня нет никакой проверки субъекта | **Закрывается** — типы без измерений, включая для `admin` |
| Построчные ограничения по `BRANCH`/`JOURNAL` | Не затронуты | Не затронуты |

Практический вывод: до включения enforcement пилоту нужно выдать операционные строки на
8 типов, а обычной базе — определить, кому выдавать запись на типы без измерений.
Это работа пакета C5.8, и без неё включение даст отказ там, где сегодня всё работает.

## 4. Потребители решения

| Участок | Файл | Решение сегодня | После ADR-0017 |
| --- | --- | --- | --- |
| Canonical read | `CanonicalReadExecutor` | C5 entity read (FQN) **и** RLS read gate (CHECK_ONLY any-access, FILTERABLE predicates) | C5 read один раз; дубль снимается |
| Canonical write | `CanonicalWriteExecutor` | capability + RLS `requireUpdate`/`requireDelete` | + C5-операция до hooks и SQL |
| Агрегат | `MetadataDrivenAggregateSaveService` | root через `BaseService` → canonical write → RLS | + security preflight до `Saving` |
| Секции | `GenericOwnedSectionService` | RLS `requireUpdate`/`requireDelete`/`prepareRead` по owner | + C5-операция по owner |

| Flush boundary | `RlsWriteGuardBridge`, `RlsWriteEnforcementListener` | только `protectedEntity()` | финальная граница для всех write-capable типов |

## 5. До-замеры: статическая база (не измерение)

Проверено, что измерить по имеющимся источникам нельзя: в `logs/app.log` нет ни одного
SQL по `access_grant` (при `show-sql=false` и пороге медленных запросов 100 мс),
`pg_stat_statements` в обеих базах не установлен. Поэтому ниже — бюджет запросов по
вызовам, а не снятое измерение.

| Решение | Запросов к `access_grant` |
| --- | --- |
| C5 read allow прямым грантом | 1 (`findBySubjectTypeAndSubjectKeyAndDimension...`) |
| C5 read отказ | 1 + число назначенных ролей, с остановкой на первой разрешающей роли |
| RLS `canUpdate`/`canDelete`/`hasAccess` | 2 всегда (гранты пользователя + гранты ролей) |
| RLS отказ по FILTERABLE-измерению | +1 (`countByDimension`), для CHECK_ONLY не выполняется |
| RLS чтение (`getReadableIds`/`hasAnyAccess`) | кэш на Vaadin-сессию (`RlsReadableIdsCache`), инвалидация по `AccessGrantVersion` |

Следствие по пилоту: одно сохранение документа проходит минимум четыре независимые
RLS-проверки одной и той же сущности — два ручных `requireUpdate` в
`AccountingObjectSaveService`, авторизация корня в `CanonicalWriteExecutor` и проверка
owner в `GenericOwnedSectionService`, — то есть ≥8 запросов к `access_grant` только на
них, плюс C5-чтения `Workshop`, `Nomenclature`, `AccountingType` и записи регистра.
Ни одна из этих проверок не переиспользует решение предыдущей: снимка на вызов нет.
Числа — нижняя оценка по вызовам; точное измерение требует харнесса
(`statement inspector` в тесте), и его следует снять первым шагом C5.6 до введения
потолков.
