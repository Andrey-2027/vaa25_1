# Типы отчётов включаются конфигурацией: JRXML и UniDR (2026-10-27)

- Дата: 2026-10-27.
- Основание: запрос владельца — «должна быть настройка конфигурации: включать отчёты типа
  JRXML и включать отчёты типа UniDR; окно выбора отчётов должно позволять создавать те типы,
  которые доступны (включены в конфигурацию)».
- Смежное: [M2.2.2](m2-2-2-report-ui-20261026.md), [M2.2.3](m2-2-3-cutover-20261026.md),
  [поправка про маршруты](m2-2-2-route-registration-20261027.md).

## 1. Что нашлось

Видимость типа отчёта решалась **наличием портов поставки**, а не настройкой развёртывания:

- JR-сервисы безусловны, поэтому выключить JR было нельзя вовсе — тип предлагался всегда;
- бин UniDR условен по `app.unidr.enabled`, но у настройки не было второго смысла: каталог
  читал «есть ли `UniDrCatalogGateway`», то есть видимость типа зависела от сборки поставки,
  и выключение пилота совпадало с отсутствием бинов случайно.

Пути входа создания были распределены по экрану: окно «Новый отчёт», строки каталога и
импорт JSON (UniDR) — три независимых решения, каждое со своим ответом.

## 2. Решение

- `org.ipro.report.ui.config.ReportTypeAvailability` (platform-report-vaadin, новый) —
  запись `(jrxmlEnabled, unidrEnabled)` с `enabled(ReportEngineType)` и `enabledTypes()`.
  Таблица полная: новый `ReportEngineType` ломает компиляцию, а не получает молчаливое «нет».
- `ReportUiAutoConfiguration.reportTypeAvailability` читает `app.jrxml.enabled` (умолчание
  `true` — JR-сервисы безусловны) и `app.unidr.enabled` (умолчание `false` — пилот);
  `@ConditionalOnMissingBean`, приложение вправе подменить.
- `ReportCatalogView` — **единственное место** решения: `offeredTypes()` фильтрует строки
  каталога, окно «Новый отчёт» и импорт JSON; выключенный тип объясняется своим
  переключателем («выключен настройкой `app.jrxml.enabled=false`»), включённый тип без портов
  поставки — «не подключён в этой поставке». Эти два состояния различаются на экране.
- Выбор из одного варианта — лишний шаг: «Новый» сразу открывает создание включённого типа;
  при нуле включённых типов показывается отказ с именами обоих свойств.
- `src/main/resources/application.properties` — блок «Типы отчётов» с обоими
  переключателями и границей «настройка — есть ли тип в приложении, наличие бинов — собран ли
  он в поставке».

## 3. Проверки

- `ReportTypeAvailabilityTest` (1/0) — независимость переключателей (четыре комбинации).
- `ReportCatalogViewTest` (6/0) — строки каталога по включённым типам, состав окна
  «Новый отчёт», скрытие импорта UniDR, подсказка с именем выключенного свойства,
  различие «выключен» / «не поставлен».
- Адресный прогон: `mvn -o -B -Dvaadin.skip=true -Dtest='ReportTypeAvailabilityTest,ReportCatalogViewTest' test`
  — 7 тестов, 0 failures/errors, BUILD SUCCESS.

## 4. Живая приёмка (localhost, профиль `dev`, `admin`)

Три запуска стенда, каждый остановлен после проверки:

1. **Умолчания (оба включены):** каталог показывает оба типа; «Новый» открывает окно
   «Новый отчёт: выберите тип» с двумя вариантами.
2. **`--app.jrxml.enabled=false`:** каталог показывает только UniDR-строки; «Новый» ведёт
   сразу в редактор UniDR, окна выбора нет.
3. **`--app.unidr.enabled=false`:** каталог — одна строка JR; подсказка
   «Недоступно: UniDR — выключен настройкой app.unidr.enabled=false.»; кнопка импорта
   UniDR отсутствует; «Новый» открывает «Новый отчёт JR (.jrxml)» напрямую.

## 5. Границы

- Настройка про тип целиком; печать из карточек (`ReportPrintAction`) — отдельный шов и
  переключатель не читает. Если потребуется «тип выключен для всего приложения», это
  следующий шаг, а не забытая половина среза.
- Полный `verify` для этой правки не пере-прогонялся: она не касается отчётного runtime.
  Состояние полного гейта на дату записи — в baseline, раздел «Полный verify 2026-10-27».
