# AF6 — этап 3: контекст, виды, CatalogOwner и команды (08.11.2026)

## Результат

Снято ограничение этапа 2 на настройки команд узла. EmbeddedListHost применяет
его неизменяемый ListCommandLayout поверх экземплярного слоя уже созданного списка.
Для этого добавлен ListForm.configureCommandLayout; прежний configureCommands(Consumer)
сохранён и делегирует этому входу. Другой список/открытие не получает эти правки.

CommandOverride получил необязательный title; прежний конструктор из четырёх
аргументов сохранён. command(id).title(...) меняет только представление команды:
кнопку, пункт «Ещё», aria-label и tooltip icon-only. При наследовании/возврате
к базовому слою сохраняются исходный заголовок, иконка и обработчик; иконки
в меню не дублируются. ActionDefinition и ActionPolicy не изменены.

Объявленное действие включается в состав через include(id) или commands(...).
Объявление и обработчик берутся из существующих ActionRegistry/ActionHandlerRegistry.
Слой встраивания не разрешает создание при запрете прав/read-only и не снимает
требования выделения/обязательного контекста. Новых suppress-бинов нет.

## Контекст

ItemForm собирает изменения полей USER/HANDLER до завершения каскада обработчиков.
Для затронутых l.value обновляется фиксированный контекст существующего списка
текущими значениями редакторов. Биндинги в родителя не применяются. Загрузка и
saved state синхронизируются после целого снимка/onLoaded, а не на промежуточных
событиях заполнения. Уже созданный список скрытой вкладки получает новый отбор;
новый список скрытого места не создаётся.

Пустой источник удаляет старый список и показывает подсказку; восстановление
источника создаёт список при показе. Пустая строковая константа описания теперь
отклоняется: стандартная нормализация контекста не должна молча снимать ограничение.
Сброс пользовательских отборов и сохранённый вид не изменяют слой ограничений открытия.
Ссылка на родителя не попадает в переносимое состояние вида.

Прямые ограничения открытия и обязательный журнал передаются как initialValues
новой карточке штатным callback координатора. Вложенные пути и коллекции
остаются отбором, не присваиванием реквизита. Дополнительный механизм CRUD не введён.

CatalogOwner проверен на опубликованных платформенных owner-fixtures со штатными
ItemForm/ListForm: связь выводится из дескриптора без setFilter, сохраняется после
сброса/смены вида, попадает в новую карточку; владелец заблокирован для замены.
Серверная политика владения и модели приложения не менялись.
