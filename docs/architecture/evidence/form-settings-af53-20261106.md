# AF5.3: сравнение плоской карточки и дерева

Дата: 06.11.2026. **Расхождений нет.** Полный прогон не выполнялся.

Добавлен `src/test/java/org/ip/form/ItemFormRenderParityTest.java`.
Для каждого конкретного типа с контрактом IdentifiableEntity из рабочего каталога
и объявлений ItemFormCustomization создаются две независимые generic-карточки:
плоским конструктором и через ItemFormLayout с одним RemainingFieldsNode.
Также учитываются классы строк секций. Перечня конкретных сущностей в тесте нет.

## Что сравнивается

- Состав и порядок привязок проверяются по настоящим метаданным формы.
- Подпись и обязательность BindingDescriptor сверяются с FieldMetadataInfo.
- Видимая подпись читается из FormItem, отдельно от реестра привязок;
  собственная подпись редактора очищена, дублирования нет.
- Порядок компонентов определяется обходом построенного дерева по идентичности
  компонентов привязок, независимо от порядка самого реестра.
- Полученные снимки сравнивают имена, обе подписи, обязательность привязки,
  свойство required редактора и его класс.

Динамический тест на каждый тип даёт адресное сообщение об ошибке. Дополнительно
проверяется, что каталог непустой и содержит поля: успешная проверка не может
состоять только из пустых карточек. Случаи без опубликованных полей также
сравниваются, без исключения из обхода.

## Объём

| Вход метаданных | Типов | Полей | Обязательных |
| --- | ---: | ---: | ---: |
| EntityMetadataInfo из рабочего MetadataResolver | 23 | 70 | 55 |
| Fallback RowMetadataInfo, включая строки секций | 9 | 11 | 6 |
| Всего | 32 | 81 | 61 |

У fallback-карточек плоский путь использует настоящий конструктор
`ItemForm(Class, List<FieldMetadataInfo>, FieldFactory)`. Текущий конструктор дерева
принимает только EntityMetadataInfo, поэтому тест оборачивает настоящие поля
RowMetadataInfo в тестовый EntityMetadataInfo с kind PLAIN и без аннотации.
Это адаптация входа теста, не изменение intent сущности или производственного API.
Она сравнивает поля и редакторы; равенство getMetadata() для этих двух входов
не заявляется. Объединение конструкторов относится к AF5.4.

Тест сравнивает generic-пути, а не заменяет прикладные варианты автоформами.
Проверка настоящих фабрик и вариантов из AF5.2 запускается отдельно в том же пакете.
DataInitializer и LookupService заменены mock, остальные метаданные и FieldFactory
настоящие. На каждый случай создаётся свой UI с восстановлением прежнего в finally.
Записи не открываются и не сохраняются.

Первоначальная попытка компиляции через прежний изолированный кэш
(`af53-targeted.log`) не видела новый RemainingFieldsNode: замена classpath
Surefire действует только во время выполнения, а компилятор использовал старый JAR.
Итоговый запуск выполнен через обычный Maven-кэш с установленной сборкой AF5.1.
Для согласования зависимостей в него установлены уже собранные локальные
entity-design-core/json/source из изолированного кэша; исходники этих модулей
в AF5.3 не менялись. Кэш работающего приложения не заменялся.

Это проверка построенных компонентов, не браузерная визуальная приёмка.
AF5.4 — перевод конструкторов на один движок — не начинался.
