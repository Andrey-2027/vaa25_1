# AF5.1: новые узлы компоновки

Дата: 06.11.2026. Полный прогон не выполнялся по указанию владельца.

## Изменения

- RemainingFieldsNode с неизменяемым `.except(...)`: опубликованные, не скрытые
  поля в порядке order, за вычетом явных полей всего дерева и исключений.
  Два места для остальных и неизвестные исключения отклоняются до рендера.
- SectionNode с классом строки: отложенное подключение таблицы в нужное место,
  включая вкладку. Фильтр состава секций и read-only сохраняются. Неуказанные
  секции продолжают отображаться внизу по прежнему правилу.
- ItemSectionHost хранит общий список для жизненного цикла и отдельный список
  нижних секций для отображения; таблицы в дереве участвуют в тех же операциях.
- Идентификаторы панелей и вкладок, заголовок панели; старые конструкторы сохранены.
- CustomNode принимает фабрику, вызываемую на каждую форму; прежний конструктор
  с готовым компонентом и accessor component() сохранены.
- Новые типы внесены в реестры поверхности. Новый публичный метод
  ItemForm.validateSectionLayout используется фабрикой до подключения таблиц.

Примеры и правила: [узлы карточки](../../forms/item-form-layout.md).
Прикладные формы не мигрировались; AF5.2–AF5.5 не реализуются этим изменением.

## Проверки

`outputs/verification/af51-vaadin-targeted.log`: 37 тестов, без ошибок:

- ItemFormLayoutNodesTest — 12 новых сценариев: порядок и binding остальных,
  поля на последующей вкладке, исключения, дубли, секции на вкладке и снизу,
  фильтрация секций, read-only, родитель и проверка строк, идентификаторы,
  заголовок группы, отдельные компоненты из фабрики, прежние конструкторы,
  отсутствие пустой нижней области, когда все секции размещены в дереве.
- ItemFormLifecycleTest — 7.
- TableSectionColumnsTest — 7.
- ItemFormInitialValuesTest — 3.
- VaadinModuleCompositionTest — 8.

Тестовый обход вкладок использует TabSheet.getComponent(tab): содержимое
Vaadin-вкладок до присоединения к UI не входит в обычный getChildren().

Для проверки приложения используется собранный AF5.1 JAR через дополнительные
элементы classpath Surefire с исключением старого platform-vaadin из зависимостей.
Это сохраняет кэш работающего приложения. Обычный Maven-кэш содержит другую
версию зависимостей entity-design; первая попытка целевого запуска из него
остановилась на компиляции EntityDraftRegisterUiTest, до выполнения тестов
(`af51-application-targeted.log`). Код этих зависимостей не менялся в AF5.1.

Основной целевой запуск приложения: `af51-application-targeted-isolated.log`:
14 тестов прошли (FormSettingsSnapshotTest — 4, PlatformApiBaselineTest — 4,
PlatformVaadinSurfaceTest — 6). Снимок настроек P2 совпал без перезаписи.
Эталон API обновлён намеренно только для platform-vaadin. Этот запуск предшествовал
финальному скрытию пустой нижней области; последнее исправление проверено
целевыми тестами модуля. Повторная проверка финального API без перезаписи —
`af51-api-final.log`: 4 теста прошли без перезаписи.

Отпечаток platform-vaadin обновлён: 249 файлов,
`9aebe46716be6064e340862096e5d6aa15c47094e09a7f45a93c6b5b01ca6cea`.
Библиотека собрана; новый JAR установлен в обычный локальный Maven-кэш.

Bootstrap ValidateOnly (`af51-bootstrap.log`) проходит новый отпечаток
platform-vaadin и останавливается на том же отдельном дрейфе platform-report-vaadin,
зафиксированном до AF5.1 (33 → 34 файла). Его отпечаток не менялся.

Браузерная приёмка новых прикладных экранов не заявляется: AF5.1 добавляет
узлы движка, существующие формы используют прежнюю компоновку. Пилот нового
API и его визуальная приёмка предусмотрены AF5.5 / К3.
