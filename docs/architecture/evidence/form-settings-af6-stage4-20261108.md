# AF6 — этап 4: пилот Workshop (08.11.2026)

Основание — принятый владельцем эскиз (§12.41 рабочего плана).

## Реализация

- `WorkshopItemForm`: поля код/наименование/филиал перенесены на вкладку
  «Основное» с сохранением ширины редакторов. Вкладка «Входящие накладные»
  содержит ленивый список ReceivingDocument с `receivingWorkshop = self`.
- `ReceivingDocumentListFormConfig`: добавлен именованный вариант
  `workshop-incoming`, колонки — number, date, journal, transferringWorkshop.
  Общая панель журнала/периода наследуется; цех-приёмщик показан фиксированным
  стандартной панелью контекста, без второго редактируемого значения.
- Экземплярный слой переименовывает создание в «Создать накладную», исключает
  копирование и удаление, оставляет создание/обновление на панели. Остальные
  доступные команды, в том числе виды, располагаются в меню «Ещё».
- До первой записи — штатное сообщение вместо списка; без чтения документа
  вкладка скрыта. Журнал блокирует только создание, не просмотр.
- Стандартный координатор разделяет ключи видов `ReceivingDocument` и
  `ReceivingDocument.workshop-incoming`. Default-колонки и selection-колонки,
  основной список и его команды не изменены. Платформенный код не менялся.

## Проверки

**Итог: 53 целевые проверки прошли без ошибок и пропусков:** 9 EmbeddedListRuntimeIT
в финальном повторе, 38 ItemFormConstructionTest, 4 WorkshopItemFormTest и
2 ReceivingDocumentAutoformIT в предшествующем прогоне. После него менялась
только runtime-фикстура накладной: добавлена обязательная строка материала
и необходимые права чтения её справочников. Остальные 44 проверки не повторялись.

В `EmbeddedListRuntimeIT` добавлены сценарии рабочего Workshop через настоящий
FormResolver и фабрику списка: ленивое создание/первая запись; скрытие вкладки
по C5; создание накладной кнопкой с передачей журнала и цеха; сохранение через
обычный координатор вместе с обязательной строкой материала; SQL-чтение только входящих, без исходящих; сохранение
ограничения после сброса и применения вида; отсутствие dirty у карточки цеха;
независимость колонок и подписи создания основного списка.

Проверка сборки всех ItemForm по-прежнему выполняется без аутентифицированного UI:
в ней порт EmbeddedListFactory подменён с запретом чтения. Реальное разрешение
и отказ проверяются отдельно в EmbeddedListRuntimeIT, а не в тесте сборки.

Журналы целевых прогонов: `target/af6-stage4-tests.log` и
`target/af6-stage4-runtime-final.log`. Последний повторяет runtime-сценарии
после добавления обязательной строки в тестовую накладную.
Первый журнал сохраняет промежуточное падение runtime-теста на предметной
проверке пустой табличной части; финальный журнал завершён BUILD SUCCESS.
