# AF3.4: визуальная проверка 06.11.2026

Проверка AF3.4 завершена: обычное/узкое окно, компактный режим, сохранение ширины,
полный перезапуск приложения и пересохранение вида проверены. Найденное обрезание формы
при переходе к командам исправлено. **AF3.4 закрыт с согласованным исключением:**
06.11.2026 владелец указал пока не учитывать обрезание старого фильтра даты-времени,
поскольку в AF3.8 он будет заменён новым. Сам фильтр этим решением не исправлен;
его замена остаётся задачей AF3.8 и не блокирует приёмку AF3.4.

## Стенд

- Настоящее приложение `org.ip.Application`, профиль `accounting-pilot`, JDK 21,
  локальный адрес [http://localhost:18080](http://localhost:18080).
- Создана отдельная база `accounting_object_pilot_af34_20261106`, копия существующей
  `accounting_object_pilot_local_v3`. При первом старте исходной базы с `validate`
  обнаружена отсутствующая таблица `navigation_assignment`. Схема обновлена **только
  в копии**, дальнейшие запуски идут с `ddl-auto=validate`.
- Субъект — существующий `accounting-pilot`. В копию добавлено только право чтения/записи
  `ENTITY:org.ip.model.GridFormView`, необходимое для сохранения проверочного вида;
  право удаления не выдавалось. SQL ограничен точным именем копии базы:
  `outputs/verification/af34-visual-fixture.sql`. Исходная база и её права не менялись.
- Настройки Vaadin читаются из обычного `user.home=C:/Users/strim`; причина первоначального
  отказа `C:/.vaadin/userKey` устранена параметром запуска, без копирования ключей.
- Проверка через браузер: 1440×900 и 760×900 CSS px. Снимки — в масштабе 1:1;
  временная настройка viewport после проверки сброшена. Приложение оставлено запущенным,
  вкладка списка «Цеха» сохранена для пользователя.

## Исправление, найденное проверкой

Изначально строка команд не переносилась. Переход к невидимой справа кнопке
«Компактный вид» прокручивал контейнер всей формы и обрезал левый край таблицы.
В `ListForm` включён перенос команд, применён стандартный интервал Lumo `space-s`;
распорка перед «Ещё» получила нулевую базовую ширину с существующим flexGrow=1.
Без последнего изменения прежний `width:100%` принудительно создавал лишний ряд.
В обычном окне команды помещаются в строку, в узком — переносятся внутри панели.
Новых стилей в прикладных формах нет.

После финальной правки повторены 11 целевых проверок UI:
`FormResolverListColumnsTest`, `ListFormSavedViewIntegrationTest`,
`ListFormFilterGridIntegrationTest`. Сборка и проверки зелёные; полный прогон не выполнялся.
Модуль установлен в изолированный и обычный Maven repository, его fingerprint обновлён.
Публичные сигнатуры не менялись. Bootstrap ValidateOnly сохраняет прежний дрейф внешнего
filtergrid (177 → 178 файлов).
