# КИ-4: административный редактор профилей

Дата: 2026-10-10. Результат этапа — прикладной редактор поверх backend КИ-2.

## Что реализовано

При `platform.navigation.enabled=true` администратор видит вкладку «Интерфейс»
в существующем `AdminView`. `NavigationProfilesAdminTab` — prototype component,
создаваемый только во включённом режиме. Повторное подключение AdminView сохраняет
тот же редактор; возврат на вкладку не перечитывает профиль поверх локальных правок.
Неадминистратор не получает вкладку. Серверные операции дополнительно защищены
`NavigationAdministrationService`, локальные действия редактора — прикладным
`NavigationAdministrationAccess`.

`NavigationProfileDraft` хранит отсоединённый профиль с версией и локальные
переопределения. Полное дерево каталога сохраняет скрытые и пустые узлы, показывает
настройку разработчика, выбор «По умолчанию / Показывать / Скрывать» и итог.
Для скрытого предка указана причина с его названием. Предпросмотр строится тем же
`NavigationResolver` с разрешённым чтением всех типов: это состав профиля **до**
проверки прав конкретного пользователя, что явно написано в интерфейсе. Бизнес-данные
для предпросмотра не читаются, формы не открываются.

Создание и переименование используют отдельные защищённые операции. Переименование
обновляет версию, сохраняя локальный черновик видимости. Сохранение передаёт ожидаемую
версию и полный локальный состав; ошибка или конфликт не заменяет черновик и не
переходит к повторной записи без перечитывания. При конфликте переименования ошибка
видна внутри диалога, введённое название остаётся. Сброс требует подтверждения,
удаляет обычные и устаревшие переопределения и сохраняет назначения. Переключение
профиля, создание другого и явное обновление предупреждают о несохранённых правках.

Счётчик устаревших ключей виден в выборе профиля; при открытии показаны предупреждение
и отдельный список. Неизвестный пункт невозможно включить через редактор. Обычное
сохранение сохраняет такие ключи, сброс удаляет.

Назначения находятся в отдельной области: поиск по логину через bounded canonical
lookup (до 50 совпадений), текущий профиль, назначение, замена и снятие назначения.
Редактор передаёт стабильный ID из `UserOption.key`, а не введённый вручную логин/ID.
До назначения локальный состав нужно сохранить. Ошибка чтения назначения блокирует
его изменение до успешной повторной загрузки. Отказ чтения пользователей не отключает
редактирование профиля и не выдаёт дополнительных прав. Успешная запись отображается
из возвращённого результата, без обязательного дополнительного чтения, которое могло
бы ошибочно выдать уже выполненную запись за неудачную.

## Как открыть

После подготовки таблиц из КИ-2 запустить приложение с
`--platform.navigation.enabled=true`, войти администратором и открыть
«Администрирование → Интерфейс». Создать профиль, настроить видимость и сохранить;
затем найти пользователя и назначить профиль. Для поиска/назначения нужны существующие
права чтения пользователей; ROLE_ADMIN не заменяет C5. Получателю нужно обновить
страницу или войти заново. Открытые вкладки сохраняются.

По умолчанию флаг остаётся `false`: дополнительная вкладка и её bean отсутствуют,
прежние административные вкладки и сохранённые профили не меняются. Подготовка
пилотной БД, учёток и прав, браузерный сценарий на PostgreSQL — КИ-5.

## Проверки и границы

Регрессионный прогон КИ-4: **50 успешных проверок**, без отказов и пропусков.
Он включает редактор и AdminView, навигацию КИ-3, enabled/disabled application smoke,
API baseline, архитектуру и wiring адресов/закрытия вкладок. Отдельный
`NavigationEditorApplicationSmokeTest` нажимает кнопки создания и сохранения двух
профилей с разными настройками через настоящие компоненты и renderer, используя
реальный защищённый сервис и H2. Новый экземпляр перечитывает сохранённые профили.
Неадминистратору редактор отказывает; bean действительно prototype.

Компонентные проверки проходят через кнопки, ComboBox, TreeGrid renderer и события
подтверждения: три состояния, скрытый родитель, пустой узел, устаревшие ключи,
ошибка/конфликт, сохранение и переименование с новой версией, подтверждаемый сброс,
отмена переключения, два разных профиля и назначения двум пользователям, снятие
назначения, фильтр/лимит поиска, повторная загрузка и отзыв административной роли.
Назначения на этом уровне используют stub backend; настоящие FK/версии/назначения
проверены в модульной H2 интеграции КИ-2. Это не подменяет браузерную приёмку КИ-5.

Модуль: **40 успешных тестов**, PostgreSQL-тест пропущен в обычном Maven-прогоне.
Схема и Java API модуля не менялись. `NavigationNode` и `NavigationVisibility`
переклассифицированы из MODULE_API в APP_API; signature baseline остался прежним.
В reviewed-реестр приложения добавлены четыре непосредственно используемых типа;
в замеры внесена только дельта этапа. Fingerprint обновлён только для
`platform-navigation`, воспроизведён диагностикой; локальный jar установлен в Maven.

Посторонние изменения рабочего дерева сохранены. Общий surface gate ранее имел
нарушения соседнего UniDR и дрейф замеров; проверка этого gate фиксируется отдельно,
общая сборка репозитория не объявляется полностью зелёной. Финальная проверка
`PlatformPublicSurfaceTest` повторила прежние пять отказов: wildcard/FQN UniDR,
незарегистрированные отчётные типы/`RlsContext`, legacy `EntityRef` и дрейф замеров
(240 прикладных исходников против документированных 202). Навигационные типы в
нарушениях отсутствуют. Три проверки manifest graph/coordinates прошли.

После двух завершающих правок (очистка выбора профиля и сообщение об ошибке внутри
диалога переименования) повторно прошли **15 проверок редактора и AdminView**,
включая два новых сценария. `git diff --check` для файлов этапа прошёл.
