# AF5.4: единый движок ItemForm

Дата: 06.11.2026. Реализовано с сохранением существующих прикладных форм.
Полный прогон не выполнялся по указанию владельца.

## Изменения

В ItemForm оставлен один внутренний конструктор и один путь рендера дерева.
Дублирующий цикл создания полей плоской карточки удалён. FieldFactory.createField
вызывается только из renderField.

- Автоформа из EntityMetadataInfo строит дерево с RemainingFieldsNode.
- Прежний фильтр имён переводится в FieldNode, сохраняя порядок метаданных,
  исключение hidden и значение «все поля» для null/пустого списка.
- Конструктор Class + List<FieldMetadataInfo> переводит переданный список в
  FieldNode, сохраняя его порядок и состав, включая явно переданные hidden-поля.
  getMetadata() у этого входа по-прежнему null. Поля рендера хранятся отдельно,
  поэтому создание редакторов строки не требует EntityMetadataInfo.
- Явное дерево и совместимые входы используют тот же основной FormLayout;
  getFormLayout() больше не возвращает null для кастомного дерева.
- Сборка происходит сразу в конструкторе. Поля и основная область доступны
  подклассам после super(...), без отложенных вызовов layout()/adjust().
- Сигнатуры публичных конструкторов и методов не менялись.

FormResolver уже направляет входы в эти конструкторы, поэтому менять его не
потребовалось. UserItemForm, CorrectionForm, форма строки корректировки,
NomenclatureItemForm, AttributeTypeForm, SklNomOpaForm, NomAttributeValueItemForm
и остальные производственные формы не изменены и не удалены.

Примеры и совместимость: [узлы компоновки](../../forms/item-form-layout.md).

## Проверки модуля

`outputs/verification/af54-vaadin-targeted.log`: **80 тестов, без ошибок и пропусков**.
Запущены ItemForm*Test, TableSectionColumnsTest и VaadinModuleCompositionTest.
Это целевая группа, не полный прогон модуля.

ItemFormLayoutNodesTest расширен до 14 сценариев. Новые проверки подтверждают:

- основная область существует и принадлежит форме при каждом входе конструктора,
  включая явное дерево, пустой фильтр имён и карточку строки;
- добавление собственного компонента через getFormLayout() работает и у дерева;
- фильтр имён сохраняет порядок метаданных и не возвращает hidden;
- конструктор строки сохраняет произвольный переданный порядок и явно переданное
  hidden-поле, getMetadata() остаётся null;
- подкласс сразу после super(...) получает поля, подключает обработчик и
  добавляет свой компонент в основную область.

username находится перед вручную добавленными паролем и ролями; оба редактора

`correctionFormRecalculatesComparisonWithoutDiscardingDraftRows` и

и реакция редактора строки на изменение выбранного значения.

Снимок P2 и эталон API совпали без обновления. AF5.3 до этого изменения сравнил
независимые движки; после удаления плоского пути его тест продолжает проверять
совместимость старых входов с явно заданным деревом и настоящими метаданными.
