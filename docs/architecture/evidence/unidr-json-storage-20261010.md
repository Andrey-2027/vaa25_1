# UniDR: определения отчётов в JSON-файлах

Дата: 2026-10-10. Основание: пользователь предложил пока хранить отчёты в JSON
и согласовал этот вариант. Личные варианты остаются отложенными.

## Хранение и интерфейс

По умолчанию используется `reports/unidr/` относительно рабочего каталога сервера.
Свойство `app.unidr.file-store-dir` позволяет указать абсолютный постоянный путь.
Папка создаётся при первом сохранении и исключена из Git; для переноса и резервного
копирования нужны сами JSON-файлы из этой папки.

Один файл `<id>.json` содержит `fileVersion: 1`, неизменный положительный `id`,
`author`, `description` и `definition` — существующий рецепт UniDR с собственной
`schemaVersion`. Сохраняются ручной/визуальный запрос, определения параметров,
поля, группировки, отборы, итоги, сортировки, формулы, оформление и номер строки.
Введённые значения последнего запуска и данные результата в файл не записываются;
значения по умолчанию входят в определение параметров.

В редактор добавлены «Открыть…», «Сохранить», «Сохранить как…», состояние сохранения
и ссылка на общий каталог. Первое сохранение и создание копии запрашивают название
и описание. Открытие показывает таблицу с поиском, названием, описанием и автором.
После сохранения/открытия адрес имеет вид `/unidr?id=<id>`; обновление страницы
восстанавливает рецепт. Незавершённые изменения параметров запроса нужно применить
перед сохранением. При ошибке сохранения текущий черновик остаётся в редакторе.

Определения общие: авторизованный пользователь может открыть чужой отчёт и сделать
копию; перезапись доступна автору. Копия получает новый идентификатор. Переименование
сохраняет идентификатор и имя файла. Названия не должны повторяться без учёта регистра.

## Каталог и границы

Добавлен движок `UNIDR` с подписью «UniDR». `UniDrCatalogContributor` передаёт
метаданные файлов в существующий `ReportCatalogService`, сборка строки остаётся
в `ReportCatalogItemFactory`. Старый конструктор сервиса сохранён. В общем каталоге
открытие и запуск UniDR ведут в редактор соответствующего JSON-файла; создание
UniDR предлагается при включённом пилоте. Копирование выполняется через
«Сохранить как» редактора; удаление и экспорт рецепта из общего каталога не добавлены.

При выключенном `app.unidr.enabled` файловое хранилище и поставщик каталога не
регистрируются. Схема БД и хранилища старых движков не изменены. Назначение UniDR
контекстным объектам через меню печати этим дополнением не реализовано.

Все публичные операции хранилища проверяют доступ UniDR. Сохранение и загрузка
проходят существующий JSON-кодек/валидатор, включая проверку источника запроса.
Перечень файлов читает только метаданные, без исполнения/анализа запросов.
Повреждённые файлы пропускаются в списке с диагностикой в журнале; явное открытие
отвечает ошибкой. Файл не заменяется начальным примером и не исправляется автоматически.

Запись использует временный файл в той же папке, принудительный сброс и атомарную
замену. Между экземплярами хранилища применяются файловая блокировка и сравнение
SHA-256 текущего содержимого с прочитанной ревизией. Устаревшее сохранение получает
ошибку с предложением открыть заново или сохранить копию. Произвольный путь от
клиента не принимается; проверяются версия, структура, размер и соответствие ID
имени файла. Папки и файлы с символическими ссылками не используются.

## Проверки

Изменённые main-классы скомпилированы Java 21 с `-sourcepath src/main/java`, затем
перекомпилированы 29 классов тестов и их зависимости. Использован зафиксированный
classpath последнего UniDR gate из `outputs/unidr-u4/compile.args`; это адресная
проверка, не новый полный Maven build всего многомодульного проекта.

- Адресный запуск: **54/54**, `outputs/unidr-u4/files-gate.log`.
- Расширенный запуск: **261 успешная проверка из 273**,
  `outputs/unidr-u4/files-full-gate.log`. Оставшиеся 12 получили ошибку подготовки
  H2 из-за неправильного порядка ресурсов в самописном JUnit Launcher:
  `target/classes` предшествовал `target/test-classes`, и подставлялся PostgreSQLDialect.
- После исправления порядка classpath все эти **12/12** прошли в отдельном процессе:
  `outputs/unidr-u4/files-query-gate-corrected.log`. Таким образом, все **273**
  проверки выбранного набора успешны, включая реальные чтения/RLS/экспорт на H2.

Проверены полный файловый round-trip, запрос и определения параметров, UTF-8,
создание копии, сохранение ID, коллизии названий, конфликт вкладок и ручной правки,
два одновременно сохраняющих экземпляра, повреждённые/большие/неверсионированные
файлы, авторство и отказ без доступа. UI-проверки покрывают сохранность черновика,
очистку состояния изменений и диалог сохранения. Проверены поиск и объединение
каталога, переход UniDR по `(type, id)`, прежние сценарии UDR/UReport3/JR и единая
граница сборки строки каталога. Существующие проверки рендера, параметров, формул,
границ, PDF/XLSX и редакторов запроса также прошли.

В браузере на изолированном H2-пилоте localhost:8086 проверены создание файла,
изменение названия, обновление страницы с `id`, отдельная копия с описанием,
список двух файлов и открытие исходного отчёта. Файлы остались в `reports/unidr/`:
`2691860656009858881.json` и `905729777375203255.json`.
Снимок: `outputs/unidr-u4/json-files-browser.png`.

Старый готовый frontend-пакет стенда не соответствовал серверным модулям, клиент
не принимал RPC. Стенд перезапущен с `--vaadin.frontend.hotdeploy=true`; Vite собрал
актуальный frontend, и браузерный сценарий выполнен. Этот аргумент добавлен в
`scripts/run-unidr-u4-smoke.ps1`. Общий каталог проверен компонентными тестами:
изолированный браузерный стенд сканирует только маршруты UniDR. Полная загрузка
основного приложения и практическая пользовательская приёмка остаются отдельными
проверками. Загрузки PDF/XLSX через браузер в этой итерации не выполнялись.
