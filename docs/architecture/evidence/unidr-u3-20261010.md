# UniDR U3: сборщик отчёта и экспорт

Дата: 2026-10-10. Продолжение [U2](unidr-u2-20261010.md).

## Карточка решения

| Пункт | Решение |
| --- | --- |
| Цель | Сформировать из настройки и отделённых строк U2 проверяемый отчёт, preview и файлы PDF/XLSX |
| Режим | Серверный пакет пилота U3; редактор и пользовательская проба остаются U4–U6 |
| Основание | Запрос U3 с независимыми границами строк/колонок, чередованием цветов строк и разрешением использовать экспорт UDR |
| Входит | Native DR columns/groups/subtotals, оба режима, оформление, PDF preview, экспорт одного JasperPrint, включение рендера в worker/quota |
| Отложено | Vaadin view, UI controls/iframe/resources U4, сохранение и личные варианты, произвольные цвета/шрифты/макеты |
| Критерий завершения | Настройка без UI формирует ожидаемые групповые/общие значения и читаемые PDF/XLSX; экспорт не читает БД повторно |
| Следующий пакет | U4: редактор, параметры, показ результата и кнопки экспорта |

## Код и контракт

Новый сборщик `org.ip.unidr.render.UniDrReportCompiler` напрямую использует
DynamicReports, по подтверждённому U0 способу. Модель бэндов UDR не создаётся,
Spring-бин `ReportCompiler` не подменяется. Старые редактор, preview dialog и
компилятор UDR не меняются; их действующий ReportCompiler экспортирует готовый
UniDR JasperPrint в PDF/XLSX.

`compile(definition, dataset)` валидирует настройку, нужные поля и типы. ID и
подписи группы читаются из разных aliases, дата остаётся LocalDate, количество —
BigDecimal. Скрытые поля регистрируются для DR, но не становятся видимыми колонками.
Порядок строк U2 сохраняется. Повторное появление уже закрытой группы отвергается:
неправильно отсортированный dataset не выдаётся за корректный отчёт.

На каждый уровень автоматически добавляются выбранные меры. SUM/AVG/MIN/MAX
считаются по исходным строкам штатными subtotals DR; среднее не вычисляется из
средних дочерних групп. COUNT_ROWS использует `count(exp.value(1))`, включает
позиции с NULL количеством и не требует marker/ID-колонки. MIN/MAX явно
сопоставлены LOWEST/HIGHEST, AVG — AVERAGE текущей библиотеки.

- SUMMARY: колонка группы и выбранные меры, `subtotalsAtGroupHeader`, скрытые детали.
- DETAILS: выбранные колонки в пользовательском порядке, меры без дублирования
  выбранного поля, заголовки групп и `subtotalsAtGroupFooter`.
- Одинаковые подписи разных ID не объединяются. До трёх уровней, включая дату.
- Общий итог определяется `grandTotal`. В SUMMARY без групп и без общего итога
  остаётся одна строка «Итог», чтобы запрос агрегатов не дал пустую таблицу.
- Пустой dataset формирует читаемую страницу с названием и сообщением об отсутствии
  данных; ложные итоги не печатаются.

Шрифт DejaVu Sans с кириллицей встраивается в PDF. Количество форматируется
`#,##0.00`, счётчик — `#,##0`, дата — `dd.MM.uuuu`. Текст не интерпретируется как
markup. Длинные подписи растягиваются по высоте. Страницы A4, широкая таблица
выбирает landscape; нумерация страниц на русском.

Для текстовой подписи заголовка SUMMARY используется `customValue`, без агрегирования. Текущая DR
принудительно ставит GROUP evaluation всем subtotals заголовка группы, что мешает
Jasper измерить длинную подпись до печати. Перед компиляцией в сгенерированном
JasperDesign только ячейки подписи этих заголовков переводятся в NOW. Числовые
итоги сохраняют штатное отложенное вычисление. Это локальная адаптация UniDR;
внешняя библиотека не изменена. Перенос проверен в обоих режимах и визуально.
Подпись footer в DETAILS сохраняется в переменной DR `Calculation.NOTHING`, чтобы
при переходе на следующую группу не прочитать уже новые значения полей.

## Оформление

`UniDrDefinition.Appearance` добавлен как необязательный объект JSON v1:

```json
"appearance": {
  "rowBorders": true,
  "columnBorders": true,
  "stripeRows": true
}
```

Старый v1 без appearance получает все три true. Если объект передан, требуются
три настоящих boolean, без coercion или молчаливого дефолта для неверного значения.
Старый Java-конструктор определения сохраняет стандартное оформление.
Пример `examples/unidr/receiving-items-v1.json` обновлён.

Горизонтальные и вертикальные границы независимы; применяются к заголовкам,
детальным ячейкам, групповым и общим итогам. Пустые ячейки итоговой строки тоже
получают стиль. `stripeRows` чередует белый и светлый серо-голубой фон:
в DETAILS — строки данных, в SUMMARY — видимые строки групп. Для SUMMARY
предварительно нумеруются префиксы ключей групп; число скрытых detail-строк
не меняет порядок полос. Пользовательская палитра в этот пакет не входит.

## Запуск, preview и экспорт

`UniDrRunService` сначала получает Data U2, затем формирует макет в том же worker.
Слот общей ReportRunQuota удерживается до завершения рендера; освобождается
также при ошибке макета. Компилятор отвергает активную транзакцию вызывающего
кода: построение страниц не удерживает транзакцию чтения.
Отменённый после чтения запуск пропускает ненужный рендер. Ревизии/session/close
U2 продолжают подавлять публикацию устаревшего результата.

В `UniDrRunResult` добавлен `report: UniDrRenderedReport`. Внешний потребитель
получает только файлы; mutable JasperPrint остаётся внутри объекта:

```java
var preview = result.report().preview(); // тот же PDF, что скачивание
var pdf = result.report().export(ReportExportFormat.PDF);
var xlsx = result.report().export(ReportExportFormat.XLSX);
// Download: fileName(), mimeType(), bytes()
```

Каждая операция проверяет текущего владельца и app.unidr.enabled, в том числе
при выдаче уже закэшированного файла. PDF и XLSX экспортируются лениво, один
раз на формат, из одного print. Кэш принадлежит одному результату запуска;
общего хранилища по UUID нет. Байты возвращаются с защитным копированием,
ошибки имеют безопасное сообщение и не сохраняются как успешный файл.
Проверка доступа относится к владельцу уже сформированного снимка; экспорт
не повторяет запрос данных. Поддерживаются только PDF/XLSX.

Preview выбран через PDF по образцу UDR — уточнение первоначального HTML-варианта
U0 по текущему запросу пользователя. `preview()` возвращает тот же PDF Download.
Vaadin iframe и download resources подключаются в U4 с проверкой владельца
при запросе ресурса; готовность пользовательского экрана в U3 не заявляется.

Для XLSX выставлены свойства JasperPrint detectCellType и удаления пустых строк.
Exporter UDR читает эти настройки: показатели остаются числовыми ячейками,
а не локализованными текстами вида «36,00». Отдельного агрегатора для Excel нет.

## Проверки и повторный запуск

```powershell
./scripts/run-unidr-u3.ps1 -MavenCommand '<path-to-mvn.cmd>' -JavaHome '<JDK-21>'
```

Скрипт компилирует UniDR и реальные используемые зависимости из исходников,
включая старый JasperReportCompiler и расширение JPQL, указанное в ресурсах
JasperReports. Тесты находятся отдельно от production-классов; Mockito работает
через startup javaagent. В прогон входят регрессия модели/JSON, U2 и общей сборки UDR.
Это отдельный scoped gate, не замена полного build приложения.

Заключительный прогон 2026-10-10, JDK 21.0.11, Maven 3.9.9,
DynamicReports 7.0.0-ip.20260813 и JasperReports 7.0.6:

| Проверка | Результат |
| --- | --- |
| `bootstrap-local-dependencies.ps1 -ValidateOnly -Offline` | PASS: граф, координаты и все fingerprints совпадают; manifest не изменён |
| Компиляция UniDR и используемых исходных зависимостей | PASS |
| U1–U3 и 7 регрессионных проверок сборки запросов UDR | **141 tests, 0 failures, 0 errors, 0 skipped** |
| Реальный источник, canonical lookup/C5/RLS, чтение → макет → PDF/XLSX на H2 | 9 интеграционных проверок, PASS |
| Визуальная проверка | PASS: summary/details и все 3 страницы multipage; дополнительно длинная подпись в обоих режимах |
| Полная `mvn -o -DskipTests compile` | FAIL: те же 21 существующая ошибка миграции IdentifiableEntity вне UniDR |

Общий build по-прежнему блокирован употреблением параметров типа у уже
нетипизированного IdentifiableEntity в формах, регистрах и print action. Ошибок в UniDR
нет; полный gate не считается пройденным. Журнал: `compile-main.log`.
U3 не меняет запрос источника. PostgreSQL-прогон U2 зафиксирован в предыдущем
evidence; новый сквозной сценарий U3 в этом пакете проверен на H2.

Проверяются 0–3 группы и оба режима; SUM/AVG/MIN/MAX/COUNT_ROWS; NULL и ноль;
одинаковые подписи с разными ключами; порядок групп; пустые данные; отключённый
общий итог; count-only и детали без мер; независимые границы и полосы summary;
JSON-совместимость; кириллица/embedded font; числовые ячейки XLSX;
95 детальных строк на нескольких страницах и ровно один общий итог;
ошибка рендера/квота; владелец/флаг при повторном экспорте; защита байтов кэша.

Интеграционный сценарий на реальных ReceivingDocumentItem и действующих C5/RLS
передаёт выборку в компилятор, получает PDF preview/PDF/XLSX и утверждает, что
число SQL statements после чтения не увеличивается.

Локальные примеры: `outputs/unidr-u3/summary.pdf`, `details.pdf`, `multipage.pdf`
и одноимённые XLSX. Из каждого PDF тест создаёт PNG всех страниц через PDFBox
для визуальной проверки. Журналы: `test.log`, `compile-scoped.log`, `compile-tests.log`.
Итоговые страницы просмотрены после последней правки: кириллица читается,
названия групп соответствуют итогам, границы непрерывны, длинные подписи не
обрезаются, все 95 позиций и единственный общий итог находятся на своих страницах.
Проверка XLSX читает XML ячеек и подтверждает числовые показатели; ручная проба
в Excel в этот пакет не входила. `baseline-validation.log` фиксирует зависимости.

Рабочий UI и хранилище личных вариантов отсутствуют по согласованному разделению
этапов. Принудительная отмена выполняющегося DR/SQL не обещается; отмена подавляет
публикацию, SQL остаётся под timeout U2. Excel сохраняет печатную структуру
JasperPrint с групповыми строками и повторёнными заголовками страниц.
