# Минимальный контракт создания PLAIN

## Состав сущности

- Самостоятельная JPA-сущность с `@EntityMetadata(kind = PLAIN)` наследуется непосредственно от `BaseEntity`. Таблица включает унаследованные идентификатор, версию и поля аудита. Редактор черновика не предлагает их как пользовательские реквизиты.
- Черновик задаёт Java-класс, пакет, таблицу, подпись типа и хотя бы один собственный реквизит. Имена `code` и `name` доступны на общих основаниях. Рецепт не добавляет эти поля, ограничения уникальности и нумерацию автоматически.
- Первый рецепт поддерживает прямые скалярные реквизиты из действующего набора типов черновика: `STRING`, `INTEGER`, `LONG`, `DECIMAL`, `BOOLEAN`, `DATE`, `DATETIME`. Ссылки, табличные части, владелец и дополнительные правила жизненного цикла находятся за границей этого рецепта. Валидация использует действующие ограничения имён, типов и параметров полей. DDL соответствует Java-мэппингу и объявленной обязательности хранения.

## Представление экземпляра

- Автор явно выбирает один из собственных строковых реквизитов как имя экземпляра. Реквизит обязателен при записи, пустое или состоящее из пробелов значение отклоняется серверной валидацией. Например, у сущности «Причина отказа» это может быть `caption`.
- Генерация передаёт выбранный путь в `@InstanceName`. Для строкового поиска штатный механизм использует этот путь. Состав колонок форм не влияет на имя или поиск. Отдельная настройка сортировки и составные имена выходят за границу первого рецепта.

## Формы

- Для типа доступны стандартные формы просмотра и изменения записи, списка и выбора. Имя экземпляра присутствует в форме записи, списке и форме выбора. Для остальных пользовательских реквизитов автор задаёт участие в этих трёх формах через действующую модель `FieldApplications`.
- Генератор помечает сущность `@FormSettingsOnly` и выпускает отдельную конфигурацию форм через `@FormConfigurationFor`. Обязательность записи задаётся моделью и серверной валидацией. Колонки и параметры отображения задаются конфигурацией форм.

## Запись

- Единственный профиль первого рецепта — `CANONICAL_CRUD` для самостоятельного типа с экспозицией `STANDARD_ROOT`. Создание, изменение и удаление используют штатные пути платформы с серверной валидацией, оптимистической блокировкой и действующими проверками доступа.
- Генерация сущности не выдаёт разрешения и не создаёт правила RLS, именованные операции или обход штатных проверок. Применение Java-файлов и SQL остаётся отдельным действием с существующими допусками.

## Критерий для следующих этапов

Минимальный черновик «Причина отказа» с единственным обязательным полем `caption` проходит JSON export/import, валидацию, генерацию Java, конфигурации форм и DDL, компиляцию и штатные операции записи. Поля `code` и `name` отсутствуют в Java и DDL. Черновики без реквизитов, с недопустимым полем представления или неподдерживаемым типом поля отклоняются до генерации.

Поддерживаемый рецепт получает собственную версию. Захваченный `custom-plain-v1` сохраняет статус `HANDOFF_ONLY`, а ранее сохранённые JSON и версии других рецептов сохраняют прежний контракт.
