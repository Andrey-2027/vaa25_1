# Глубокие ссылки: руководство прикладного разработчика (E2)

Короткое практическое дополнение к контракту
[ADR-0009](decisions/ADR-0009-deep-links.md). Здесь — что нужно сделать прикладному
разработчику, чтобы тип получил адрес, вариант стал адресуемым, а ссылку можно было выдать
пользователю; и что из этого нельзя менять необдуманно.

## 1. Адрес типа: по умолчанию он уже есть

Адрес выдаётся **не** объявлением, а следствием уже существующей классификации типа:

- тип попадает в `ManagedEntityCatalog` (у него есть `@EntityMetadata`) и не является
  `INTERNAL_STORE` → он публикуется;
- ключ адреса (`entityKey`) выводится из имени класса в ASCII lower-kebab-case:
  `GroupNom` → `group-nom`, `SklNomOpa` → `skl-nom-opa`;
- адреса два: карточка `/records/{entityKey}/{id}` и список `/lists/{entityKey}`.

Ничего объявлять не нужно. Не получают адреса по построению: строки секций (`OWNED_ROW`),
служебные хранилища без `@EntityMetadata` (`INTERNAL_STORE`) и типы вне каталога.

## 2. Именованный вариант формы становится адресуемым сам

`item=` и `list=` в baseline — это ключи, зарегистрированные в `FormRegistry`. Зарегистрировали
вариант — он появился в адресе: `?variant=key`. Литерал `default` ключом **не является**:
адрес без `?variant` и адрес с `?variant=default` — разные вещи, и второй отвергается.

Правило, которое стоит помнить: адрес получает только то, что можно восстановить **без
контекста создания**. Список с обязательным контекстным фильтром (`PrdSpec` с `journal`) поэтому
не linkable, сколько бы вариантов у него ни было. Это не запрет открыть список — это отказ
обещать адрес, который нечего восстанавливать.

## 3. Rename ключа и прежние адреса: `FormRouteAliasDeclaration`

Опубликованный адрес — обещание. Если класс переименован (или ключ должен быть иным по бизнес-
причине), объявите бин `FormRouteAliasDeclaration`: явный ключ, прежние ключи и **обязательную
причину**. Если меняется только вывод ключа, а прежние остались рабочими:

```java
@Bean
FormRouteAliasDeclaration nomenclatureRoute() {
    return new FormRouteAliasDeclaration(Nomenclature.class, "nomenclature",
        List.of("nomenklatura"), "старые письма ссылались на прежний ключ");
}

@Bean
FormRouteAliasDeclaration groupRoute() {
    return FormRouteAliasDeclaration.legacyKeys(GroupNom.class, List.of("group"),
        "ключ выведен из класса; прежний адрес остаётся рабочим");
}
```

Коллизии ключей, ключи вне грамматики и декларации для непубликуемого типа останавливают
**старт приложения** — это дешевле, чем сломанная ссылка у пользователя.

## 4. Ссылка программно

```java
FormLinkResult result = links.linkToRecord(Nomenclature.class, id);          // карточка
FormLinkResult result = links.linkToList(Nomenclature.class);                // список
FormLinkResult result = links.linkToRecord(PrdSpec.class, id, "materials-only"); // вариант
```

`FormLinkResult` — два случая, оба значимые:

- `Linkable(FormRoute route, String path)` — адрес (`path` — то, что идёт в буфер обмена);
- `NotLinkable(NotLinkableReason reason)` — `NOT_PUBLISHED`, `SCENARIO_NOT_ALLOWED`,
  `REQUIRED_CONTEXT`, `MISSING_ID`, `INVALID_ID`, `UNEXPECTED_ID`.

Отсутствие ссылки обязано быть **причиной**, а не пустой строкой: кнопка, которая молча ничего
не делает, диагностируется пользователем как дефект. В UI это уже учтено —
`CrudAction.COPY_LINK` объявлен требованием `ActionRequirement.linkable()`, поэтому
недоступность ссылки видна тем же механизмом, что и остальные ограничения действий
(см. [actions-guide.md](actions-guide.md)).

Открыть адрес программно можно тем же путём, каким его открывает host:

```java
OpenResult outcome = opener.openAddress(path);   // Opened | NotFound | Forbidden
                                                 // | InvalidRoute | NotLinkable | Unavailable
```

`outcome()` — стабильная строка для аудита; сами `OpenResult` живут в APP_API, поэтому
прикладной код может на них реагировать, а не разбирать строки.

## 5. Что приложение гарантирует и что из этого хрупко

Гарантии, на которые можно опираться:

- **Адрес не добавляет своего пути к данным.** Чтение идёт тем же canonical read, что у списка и
  карточки; построчный RLS и capability проверяются внутри него. Ссылка не обходит защиту.
- **Отказ приходит по трём различимым причинам, и это не небрежность.** Скрытая строка и
  отсутствующая — один и тот же `NotFound` (и исход, и сообщение); классовый запрет чтения
  (CHECK_ONLY-гейт) — тоже `NotFound`, потому что чтение пустое; без аутентификации — `Forbidden`,
  причём одинаковый для существующей и отсутствующей строки (отказ — про субъект, а не про запись).
  Общий смысл один: адресом нельзя проверить существование чужих записей.
- **Отказ не создаёт вкладку и не меняет адрес.** 403/404 показываются внутри рабочей области.
- **В адресе нет ни callbacks, ни параметров открытия.** Ни состояние формы, ни то, что в ней
  набрано, в историю и адрес не попадают.
- **Право перепроверяется на каждом входе**, включая повторный и переход Back/Forward.

Хрупкое — то, что ломает контракт незаметно для автора:

- переименование или удаление ключа варианта/типа: `deep-link-baseline.txt` — версионируемый
  контракт, и тест (`DeepLinkRouteBaselineTest`, `DeepLinkCatalogBaselineIT`) его удержит;
- попытка «починить» адрес вместо отказа (нормализовать регистр ключа, дополнить грамматику,
  добавить query-параметр «для удобства»): отказ — часть контракта, а не недоделка;
- выдача ссылки на форму, для которой адреса нет: это `NotLinkable` с причиной, а не пустая
  ссылка.

## 6. Чек-лист «добавил адресуемый тип/вариант»

1. Тип классифицирован метаданными (иначе он либо `INTERNAL_STORE`, либо вне каталога) — иначе
   адреса не будет вовсе.
2. Появился ключ в `src/test/resources/routes/deep-link-baseline.txt` (и при переименовании —
   прежний ключ как `legacy`).
3. Прогнаны `DeepLinkRouteBaselineTest` (по исходникам) и `DeepLinkCatalogBaselineIT` (по
   рантайм-каталогу): они ловят и то, что обещано в коде, и то, что реально попало в каталог.
4. Если у типа нестандартный список (`REQUIRED_CONTEXT`) — это осознанное решение, и оно видно
   в причине `NotLinkable`, а не в отсутствии строки baseline.
5. Ссылка проверена на двух пользователях с разным доступом: адрес не должен ничего
   рассказывать о чужих строках (приёмка — `DeepLinkTwoUserAccessIT`).
