# Собственный редактор поля

`setEditor` заменяет редактор прямого реквизита. Состав и порядок формы сохраняются.
Фабрика возвращает новый Component, реализующий HasValue:

```java
@Override protected void adjust(FormAdjust a) {
    a.element("code").setEditor(TextField::new);
    a.element("nomenclature").setEditor(this::createNomenclaturePicker);
}
```

Фабрика вызывается при сборке конкретного открытия, после конструктора формы.
При описании и стартовой проверке она не вызывается. Нельзя возвращать компонент,
уже принадлежащий другой форме. Путь реквизита проверяется при описании;
тип и экземпляр редактора — при сборке, когда компонент становится доступен.

Платформа берёт из метаданных чтение/запись сущности, обязательность, подпись и
режим чтения. `setLabel`, `setReadOnly`, `setWidth`, видимость, обработчики,
связанные подстановки и clean baseline продолжают работать. Авто-нумеруемое поле
сохраняет возможность оставить значение пустым до серверной записи.

Значение редактора должно соответствовать модельному типу поля. Неявных
преобразований, например String → Integer или BigDecimal → Long, здесь нет.
Проверяется объявленный тип HasValue, когда он доступен, и фактические значения
при чтении/записи. Для ссылочного редактора тип может быть стёрт до HasDisplayName;
фактическое значение всё равно проверяется против типа реквизита.

Фабрика собственного ссылочного редактора отвечает за его поиск и диалог.
`setSelectionVariant` одновременно с `setEditor` отклоняется: нужный вариант
настраивается внутри фабрики. Дополнительные пути и связанные отборы требуют
редактора EntityField с соответствующими возможностями поиска/диалога — прежние
проверки поддержки путей и отборов сохраняются. `bindExternal` продолжает работать.

# События EntityField

EntityField реализует HasValue. Его стандартное пустое значение — null,
`clear()` эквивалентен `setValue(null)`. Программная установка разрешена также
в read-only и вызывает стандартное событие с `isFromClient=false`. Пользовательский
выбор/очистка даёт `isFromClient=true`; повтор того же значения события не создаёт.
Подписка возвращает Registration с `remove()`.

```java
HasValue<?, Nomenclature> input = field;
Registration registration = input.addValueChangeListener(event -> use(event.getValue()));
// Когда нужна явная подписка на стандартные события самого EntityField:
field.addHasValueChangeListener(event -> use(event.getValue()));
```

Старый `field.addValueChangeListener(value -> …)` остаётся слушателем значения,
работающим только на пользовательское изменение. Прежний метод с Consumer
сохранён, включая его бинарную сигнатуру. Более специфичный совместимый
функциональный интерфейс сохраняет выбор перегрузки для лямбд и method references,
в том числе для raw EntityField. Для стандартных событий используйте HasValue,
`addHasValueChangeListener` либо явно типизированный параметр события.

`addChangeListener` по-прежнему передаёт ValueChangeSource. ItemForm наблюдает
EntityField один раз: загрузка и saved state подавляют `b.onChange`, ввод и
изменения из кода различаются, подстановка связанного поля остаётся только USER.
