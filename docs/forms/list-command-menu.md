# Команды формы списка

ListForm показывает одну строку команд и полное меню «Ещё». При сужении кнопки уходят
справа налево; меню сохраняет весь включённый состав. Скрытие по ширине не меняет
решение о доступности. Если скрывается кнопка с фокусом, фокус переходит на «Ещё».

SelectionForm использует тот же рендерер для возможностей своего грида. CRUD туда
не добавляется; «Выбрать» и «Отмена» остаются в подвале. ItemForm сохраняет свои
прежние affordance — настройки меню списка не меняют карточку.

## Умолчания

| Команда | Панель | «Ещё» |
| --- | --- | --- |
| Создать | Иконка и текст, акцент | Да |
| Копировать | Иконка | Да |
| Изменить | Иконка и текст | Да |
| Виды | Иконка | Да |
| Печать, если подключена | Иконка и текст | Да |
| Обновить | Иконка | Да |
| Просмотр, Удалить | Нет | Да, если применимы |
| Прикладные действия и ключ регистра | После основных команд | Да |
| Поиск, условия, форматирование, группировка | Нет | Подменю «Настройки» |
| Скопировать ссылку, Разработка | Нет | Подменю «Сервис» |

Возможности типа, права, выделение и обязательный контекст по-прежнему определяют
видимость и доступность. Отказ показывается подсказкой и доступным описанием,
не склеивается с названием команды. Пустые подменю скрываются. Группировка — обычный
пункт без второй кнопки или галочки; checked поиска отражает текущее состояние грида.
Пользовательского режима компактности у ListForm больше нет: сохранённое `compact=true`
игнорируется, остальные настройки вида сохраняются.

## Где настраивать

Используйте существующий бин `ListFormCustomization`, метод `configure(ListFormVariants)`:

```java
lists.commands(c -> {
    c.panel(CrudAction.CREATE.id(), CrudAction.EDIT.id());
    c.command(CrudAction.COPY.id()).iconAndText();
    c.command(ListCommandLayout.Ref.optional(ActionId.of("report.print"))).inMore();
});
```

Это выбирает две кнопки панели, но сохраняет автоматический состав полного меню.
Для именованного варианта используйте `lists.commands("review", c -> { ... })`.
Один вызов commands на вариант; объедините настройки в его consumer.
Для конкретного открытия — `form.configureCommands(c -> { ... })`.
Ни обработчики CRUD, ни обработчик печати копировать не нужно.

Полный компилируемый исходник с импортами:
[ListCommandExamples.java](../../examples/platform-consumer/src/main/java/com/example/materialrequests/examples/ListCommandExamples.java).
Он входит в обычную сборку внешнего consumer, но не регистрируется как Spring-бин.
Вложенный `RequestCommands` показывает SPI конфигурации; `review` — пример ключа варианта,
который приложение отдельно объявляет, если хочет его открывать.

## Состав и панель — независимые настройки

| Задача | Вызов builder |
| --- | --- |
| Наследовать состав | `inheritCommands()` (INHERIT) |
| Автоматический состав, включая будущие подходящие команды | `allCommands()` (AUTO) |
| Только перечисленные команды | `commands(id1, id2)` (EXPLICIT) |
| Ни одной команды | `commands()` |
| Смешанный перечень REQUIRED/OPTIONAL/LOCAL | `commandRefs(List.of(...))` |
| Наследовать панель | `inheritPanel()` |
| Платформенная панель | `defaultPanel()` |
| Все рабочие команды на панели | `allOnPanel()` |
| Только указанные кнопки | `panel(id1, id2)` |
| Панель пуста, меню сохраняется | `panel()` |

`command(id).iconOnly()` / `.iconAndText()` меняет представление, `.onPanel()` /
`.inMore()` — место, `.order(int)` — порядок панели и меню внутри группы.
`include(id)` / `exclude(id)` меняет состав без превращения AUTO в EXPLICIT.
Индивидуальный `included(true)` может включить команду поверх явного перечня.
Настройка не создаёт отсутствующий источник команды и не выдаёт право операции.
Без доступной иконки ICON_ONLY сохраняет текст, чтобы кнопка не была безымянной.

Приоритет слоёв: платформа → семейство → default сущности → именованный вариант →
экземпляр. Меняются только явно заданные свойства. Явные перечни заменяют нижние,
не объединяются с ними. Новый режим панели сбрасывает нижние индивидуальные placement,
а индивидуальное место из этого же или более высокого слоя применяется поверх него.
Настройки/служебные контейнеры автоматически в кнопки не превращаются.

## Проверка ссылок

CRUD-ключи берите из `CrudAction.*.id()`, штатные UI-ключи — из `ListUiCommand.*.id()`.
Для прикладной команды используйте её `ActionId`. `command(id)` и `commands(id...)`
создают REQUIRED-ссылки. Null, дубли и неизвестные обязательные ключи — ошибки
конфигурации с контекстом сущности/варианта; прикладной реестр проверяется с учётом
поверхности, типа и варианта.

| Ref | Когда применять | Граница |
| --- | --- | --- |
| REQUIRED | Обязательная штатная/зарегистрированная команда | Статическое разрешение конфигурации |
| OPTIONAL | Необязательный источник, например `report.print` | Отсутствие допустимо; если источник появится, действуют обычные правила |
| LOCAL | Обработчик добавляется на экземпляр через `addAction` | `UI.beforeClientResponse` после attach и композиции текущего ответа |

LOCAL до границы остаётся pending без ложной кнопки. Можно сначала настроить ссылку,
затем добавить обработчик — в том числе после возврата `createListForm`, в том же цикле.
Неразрешённый LOCAL даёт ошибку перед показом формы. Изменения показанной формы
проверяются перед следующим ответом; для произвольного будущего отсутствия нужен OPTIONAL.
`ListCommandExamples.installLocal` принимает уже существующий обработчик.

Optional печать не требует импорта классов отчётного модуля: достаточно
`Ref.optional(ActionId.of("report.print"))`. REQUIRED с тем же ключом требует
реального объявления печати. Платформенное умолчание печати необязательно.

## Совместимость и исполнение

`getToolbar(): HorizontalLayout` остаётся дополнительной областью **под** основной
строкой, до отборов/грида. Пустая область места не занимает. `add(Span/поле/Button)`
добавляет обычные компоненты туда, без автоматического пункта в «Ещё».
Индексы, обход детей и `removeAll()` относятся к этой дополнительной области.
`remove(штатнаяButton)` исключает соответствующую команду из состава; смешанный remove
поддерживается, кнопка другой формы не принимается. `removeAll()` не удаляет штатные команды.

Сигнатуры конструкторов, CRUD-геттеров, `installMoreMenu()` и `addAction()` сохранены;
повторная установка меню идемпотентна. Вложенность старого toolbar не сохраняется:
штатные кнопки больше не ищут через `getToolbar().getChildren()`.
Прямые `setVisible/setEnabled/setText/setIcon` на штатной Button не зеркалятся в меню
и могут быть перезаписаны обновлением модели. Для согласованной настройки используйте
API команд. Собственные компоненты дополнительной области сохраняют обычные Vaadin-сеттеры.

Кнопка, меню и программный `.click()` используют один dispatcher с повторной проверкой
текущих прав, контекста, выделения и включения в состав. Исключённая команда через эту форму
не исполняется, включая устаревший пункт меню; причина — NOT_APPLICABLE.
Серверные полномочия и самостоятельные серверные API настройка меню не меняет.
Подробности поведения действий — в [actions-guide](../architecture/actions-guide.md).
