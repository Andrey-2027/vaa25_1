# Связанные поля формы (AF5.8)

Связи задаются в `layout()` либо через `adjust()` после раскрытия `remainingFields()`.
Они не меняют состав или порядок полей.

```java
return l.of(
    l.field("nomenclature").setSelectionFilter("typeNom", "Материал"),
    l.field("unit").setFillFrom("nomenclature.unitOfMeasurement"),
    l.field("qt")
);
```

`setSelectionFilter(path, value)` принимает константу, `l.value("поле.путь")`
либо `l.self()`. Путь отбора относится к выбираемой сущности. `l.value` читает
текущее значение связанного редактора, включая ещё не записанный ввод, а `l.self`
означает редактируемый объект. Источник должен быть привязан на форме; его можно
скрыть через `setVisible(false)`. Пути и типы проверяются до создания редакторов.

Отбор вычисляется для каждого поиска автокомплита и каждого запроса диалога.
Изменение источника очищает выбранное значение, если оно перестало проходить
отбор. `setClearInvalidSelection(false)` сохраняет старое значение явно.

Пустой источник по умолчанию снимает соответствующее условие. Новый объект без id
для `l.self()` также считается пустым источником. Чтобы до заполнения источника
не было доступных вариантов, задайте `setAllowEmptySelectionSource(false)`.
Коллекция-константа означает IN; пустая коллекция — пустой набор выбора.

`setFillFrom("источник.путь")` заменяет значение целевого поля только после
пользовательского изменения источника, включая его очистку. Режим
`setFillOnlyIfEmpty(true)` сохраняет уже заполненное значение. Несовместимые типы
отклоняются при проверке описания; преобразования и расчёты остаются обработчиками.
Long сохраняет все 64 бита, хотя его редактор использует BigDecimal.

Зависимости подстановки и вложенных параметров автоматически добавляются к чтению
источника: LOOKUP для автокомплита/диалога, DETAIL/ROW для открытия формы и строк.
Отдельно дублировать `setLookupPaths` для подстановки не требуется. Входы обычного
обработчика, которые не описаны связями, по-прежнему объявляются явно.

`FormBehavior.Change.source()` различает:

| Источник | Значение |
|---|---|
| USER | Ввод пользователя, выбор или очистка |
| HANDLER | Программное изменение редактора, в том числе из другого обработчика |
| INITIAL_LOAD | Открытие, начальные значения или подготовка копии |
| SAVED_STATE | Применение возвращённого результата записи |

`b.onChange` получает USER и HANDLER. Подстановка получает только USER; поэтому
цепочка программных изменений не превращается в неявный каскад подстановок.
Загрузка и применение результата записи не подставляют и не очищают связанные
значения. Старый `EntityField.addValueChangeListener(Consumer)` остаётся
пользовательским слушателем; новый `addChangeListener` сообщает все изменения.

Связь отбора остаётся удобством формы. Правила допустимости записи отдельно
проверяются сервером. Модель дополнительных единиц номенклатуры (О5) этим API
не вводится и остаётся отдельным решением.
