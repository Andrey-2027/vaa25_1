# Реестр сущностей: матрица входов, вкладок и истории

Дата: 2026-11-10. Редакция 1 — конкретизация [основного плана](entity-registry-ux-plan.md) после двух частей замечаний.

## 1. Вкладки и владельцы

| Назначение | Внутренний entry id | Компонент и состояние |
|---|---|---|
| Новый реестр | `entity-explorer:registry` | Прикладной `EntityExplorerRegistryView` с платформенной панелью; состояние хранит `EntityExplorerUiSession` в текущем UI. |
| Просмотр типа T | `entity-explorer:card:<FQCN(T)>` | Отдельный `EntityExplorerCardView` на entry id; внутри платформенный `EntityExplorerCardPanel`. |
| Изменение T | `entity-modify:<FQCN(T)>` | Существующие `EntityModifyWorkspace` / `EntityModifyView`, собственная сессия изменений. |
| Общая диагностика | `entity-explorer:diagnostics` | Прикладная оболочка и платформенная панель диагностик общего снимка. |
| Создание | `entity-draft` | Существующий `EntityDraftWorkspace`; выбранный вид передаётся через его штатный контракт замены черновика. |
| Старый совмещённый экран | `entity-explorer` | Только ветка выключенного нового флага; прежний контракт до отдельного удаления. |

FQCN в таблице — внутренняя идентичность Workspace, не новый формат публичного адреса.

**Новый реестр всегда безадресен.** Выбор типа меняет обзор и состояние реестра; он не назначает реестру `/entity-explorer/{key}`. Такой адрес принадлежит отдельной карточке после её открытия. Поведение старого совмещённого экрана не переносится на новый реестр автоматически.

## 2. Матрица переходов

`push`/`replace` указаны только для отличающегося URL: повтор текущего адреса не пишет историю. «Без записи» при Back/Forward означает, что URL уже изменён браузером. Действующий dirty-guard применяется при уничтожении ввода, а не при обычном переключении вкладок.

| Вход / событие | Целевой entry id | Создание / активация | Адрес | История | Состояние | Dirty-guard |
|---|---|---|---|---|---|---|
| Меню: реестр без выбора | `entity-explorer:registry` | Создать или активировать | `/` | `replace` при смене URL | Восстановить сохранённые фильтры/раскрытия; иначе пустой обзор | Переключение не уничтожает ввод |
| Меню: реестр с сохранённым выбором | Тот же | Создать или активировать | `/` | `replace` при смене URL | Восстановить допустимый выбор, обзор, фильтры и раскрытия | То же |
| Выбрать другую сущность в новом реестре | Реестр | Остаётся активным | `/` | Без записи | Меняется только выбор и обзор реестра | Не требуется |
| Изменить фильтры/группировку | Реестр | Остаётся активным | `/` | Без записи | Меняется только состояние реестра | Не требуется |
| «Открыть карточку»: первый вход, published-ключ есть | `entity-explorer:card:<T>` | Создать | `/entity-explorer/{key}` и начальное место по действующей политике карточки | `push` | Своя карточка и своё состояние; реестр сохраняется | Переключение |
| «Открыть карточку»: та же T уже открыта | Та же карточка | Активировать существующую | Её сохранённый адрес и место | `push`, если адрес отличается; иначе без записи | Место карточки и ввод остальных вкладок сохраняются | Переключение |
| Явный адрес с допустимым якорем | Карточка названной T | Создать или активировать; применить запрос до активации | Точный допустимый адрес с `?view=` | На холодном входе без повторной записи; при Back/Forward без записи | Явное место имеет приоритет над сохранённым; реестр не меняется | По действующим правилам ухода из host; карточка не уничтожает редактор |
| Явный адрес без якоря | Карточка названной T | Создать или активировать | Допустимый адрес без якоря | Как предыдущая строка | Применить семантику адресного входа без якоря; не путать с повторной кнопкой из реестра | Как выше |
| Программный переход из формы / подсистемы | Карточка разрешённой T или владельца строки | Создать или активировать; применить переданное место | Published-адрес, если есть | `push` при смене адресованной вкладки; для безадресной — `replace("/")` | Сообщение об owned-секции доставляется именно целевой карточке | Переключение |
| Программный переход в уже активную карточку с другим явным местом | Та же карточка | Применить запрос без ожидания события активации | Адрес T с новым местом | `tabAddressChanged`: `push` при смене URL; без ключа — `replace("/")` | Программное применение места не выдаётся за пользовательский callback панели | Не требуется |
| Просмотр T без published-ключа | `entity-explorer:card:<T>` | Создать или активировать | `/` | `replace` при смене URL | Состояние карточки независимо от реестра; ключ не выдумывается | Переключение |
| Пользователь сменил раздел активной карточки | Та же карточка | Остаётся активной | Адрес этой T с её якорем | `push` при смене URL; без ключа адрес остаётся `/` | Меняется место только этой карточки | Не требуется |
| Вернуться к реестру по кнопке / вкладке | `entity-explorer:registry` | Активировать | `/` | `replace` при смене URL | Сохранить выбор/фильтры/раскрытия; карточку не закрывать | Переключение |
| «Изменить структуру…» | `entity-modify:<T>` | Создать или активировать штатным host'ом | `/`, редактор остаётся безадресным | `replace` при смене URL | Сохранить сессию изменений и все остальные вкладки | Переключение |
| «Создать новый»: поддерживаемый вид | `entity-draft` | Создать или активировать | `/` | `replace` при смене URL | Передача вида не стирает открытый черновик молча | При замене черновика — штатное подтверждение; при простой активации — без уничтожения |
| Недоступная «Простая сущность» | Текущий | Новую вкладку не открывать | Без изменения | Без записи | Показать доступное пояснение; рецепт реализуется отдельным планом | Не требуется |
| Общие диагностики | `entity-explorer:diagnostics` | Создать или активировать | `/` | `replace` при смене URL | Читать настоящие сообщения и ревизию общего снимка | Переключение |
| Закрыть фоновую карточку | Активная вкладка сохраняется | Удалить только закрытую | Без изменения | Без записи | Удалить компонент, слушатели, ссылку host'а и состояние закрытой карточки | Для редактора — если закрытие уничтожает ввод |
| Закрыть активную карточку / редактор | Следующая вкладка по штатному выбору Workspace | Активировать оставшуюся | Её адрес или `/` | `replace` при смене URL | Остальные состояния сохраняются | Для dirty-редактора — штатный guard |
| Закрыть реестр и открыть снова в том же UI | `entity-explorer:registry` | Новый компонент, прежнее состояние | `/` | `replace` при смене URL | Фильтры, группировка, раскрытия и допустимый выбор живут в UI-session, не в уничтоженном компоненте | Реестр read-only |
| Неверный адрес / нет допуска | Новая вкладка не создаётся | Штатный отказ | По действующему протоколу отказа | Без выдуманного успешного перехода | Не раскрывать существование недоступных типов | Существующий guard ухода из host |

## 3. Доступ к уже открытой карточке

Карту `entry id → EntityExplorerCardView` держит прикладной UI-scoped `EntityExplorerWorkspace`, по действующему образцу `EntityModifyWorkspace`. Это индекс ссылок на компоненты, созданные Workspace; источник фактов и фабрика метаданных из него не получаются.

1. Проверить допуск и разрешить тип/владельца/место запроса.
2. Вычислить entry id; найти существующий компонент в карте host'а.
3. Если компонент уже есть, применить **явный** адресный запрос до активации, подавляя обратный пользовательский callback смены места. Для повторной кнопки из реестра сохранить его текущее место. Проверить ревизию снимка.
4. Зарегистрировать корректный адрес именно этого entry id до активации через мост.
5. Вызвать `Workspace.open(EntityExplorerCardView.class, entryId, title, initializer)`. В initializer нового компонента передать состояние и callbacks, применить исходное место, затем добавить ссылку в карту host'а. Повторный `open` initializer не вызывает.
6. Callback изменения места замыкает entry id этой карточки. Навигационные сообщения о секции передаются в запрос конкретной карточки, а не в глобальный `Consumer<String>`.
7. При закрытии убрать ссылку и состояние карточки; при неуспешном создании убрать незавершённую регистрацию. Не обращаться обходным путём к `WorkspaceManager.getOrCreate` для чтения кеша.

Запрос различает происхождение: кнопка реестра, программная навигация, cold URL или применение истории. Для cold URL/Back/Forward адрес только регистрируется (`tabAddressed`) и повторно не записывается. Для программного перехода к **уже активной** карточке изменение адреса выполняется явно через `tabAddressChanged`, поскольку нового события активации может не быть. Для новой/неактивной карточки адрес регистрируется до её активации. Одна команда даёт не более одной требуемой записи истории.

Расширять API Workspace ради получения компонента не требуется. Сам компонент карточки не является общим UI-scoped бином; UI-scoped являются прикладной host и владельцы общего снимка/состояния.

## 4. Ограничение безадресной истории

Текущий `FormRouteUrlBridge` хранит один `addresslessEntryId`. Значение `/` само по себе не кодирует ни выбранный тип, ни идентичность реестра/редактора. По существующему контракту Back/Forward на безадресное место активирует последнюю запомненную безадресную вкладку; точное восстановление каждого такого окна из URL не обещается.

Обязательные сценарии R3: две карточки без ключа, реестр и dirty-редактор; адресованная карточка между ними; Back/Forward; закрытие последней безадресной вкладки; закрытие активной после Back. Проверить отсутствие обращения к уничтоженному entry и потери ввода. Если текущий мост нарушает зафиксированное поведение, сделать минимальное исправление с тестом. Добавление полноценной идентичности вкладок в browser history state — отдельное изменение контракта, а не скрытая часть нового реестра.

## 5. Статус проверки

Матрица — спецификация новой ветки. Текущая реализация проверена чтением `Workspace`, `WorkspaceManager`, `EntityModifyWorkspace`, `MainLayout` и `FormRouteUrlBridge`; новые прикладные классы ещё не реализованы. Тесты исполнения этой матрицы выполняются на R3/R5 и фиксируются отдельным evidence.
