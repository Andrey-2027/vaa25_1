  1. Строка команд — отдельный toolbar под заголовком, а не в шапке. У ListForm так же: commandBar — отдельный ряд над сеткой. Сначала команды над объектом из FQ-7 (пунктир) в пределах набора из определения списка, затем «Обновить» и «Виды», справа «Ещё» → «Колонки…», «Группировка», «Итоги…», «Скопировать ссылку». Поиск и условия даёт сама сетка. Панель своя, простая: модуль запросов не зависит от форм платформы. У UTR такой же отдельный toolbar, но другой набор команд.
  2. Панель параметров — над списком. Поля по виду параметра: строка, число, дата, логическое — обычные; диапазон — «с / по»; ссылка — выбор, как в редакторе запроса. Список ссылок в v1 вручную не вводится. Значения по умолчанию берутся из определения списка и между открытиями не запоминаются. Применяются кнопкой «Выполнить». Обязательные условия задаются в запросе и параметрах, а не в отборе.
  3. Строка состояния — единственное место, где видны режим и свежесть данных. В режиме «Постранично» режим не называется — только «Строк: N».
  4. Ссылка показывает представление, а отбирает выбором значения. Колонки-ссылки не сортируются ни в каком режиме; подсказка: «Для сортировки по названию добавьте в запрос колонку с названием». «Открыть <тип>» по ссылке добавит FQ-7, так же и в UTR.
  5. Группировка — панель FilterGrid слева, включается «Ещё → Группировка». Щелчок по узлу отбирает строки; счётчики и итоги узлов честные; глубина не больше трёх уровней. Итоги в подвале — по колонкам, отмеченным в стандартном виде списка. Настройка колонок, итогов и группировки — общая с UTR (UX-12), её диалоги показаны в макете UTR.

  1. Виды — как у ListForm: то же хранилище (grid_form_view), тот же формат и те же правила. Ключ — querylist.<ключ списка>[.<вариант>], по образцу ListForm (ReceivingDocument.workshop-incoming). Общий вид видят и правят все, личный — только автор. Звёздочка — вид по умолчанию для меня, переключается щелчком и применяется при открытии. «Стандартный вид» — стандартный вид из определения списка (или из варианта). Отличие от ListForm одно: «Создать» и «Изменить» берут текущее состояние сетки (колонки, ширины, сортировка, отборы, группировка), а в диалоге задаются название и «Общий». Несохранённые изменения между открытиями не запоминаются. Стандартный вид меняет только администратор в редакторе «Списки по запросу» (FQ-6). В UTR видов нет.

Тексты ошибок без текста запроса: нет доступа (тип данных), таймаут («выполнялся дольше 30 с и остановлен» + «Выполнить снова»), квота («сейчас выполняется много отчётов»), «Список требует исправления» с подробностями только администратору (в UTR — «Отчёт требует исправления», подробности автору). // объявление запроса (FQ-9): один ключ, два варианта стандартного вида
QueryListDeclaration.of("receiving.receipts", "Поступление")
    .variant("by-workshop", v -> v.hide("receivingWorkshop"))
    .variant("by-nomenclature", v -> v.hide("nomenclature"));

// карточка цеха
l.queryList("receipts", "receiving.receipts")
    .setParameter("workshop", l.self())
    .setVariant("by-workshop");

// карточка номенклатуры
l.queryList("receipts", "receiving.receipts")
    .setParameter("nomenclature", l.self())
    .setVariant("by-nomenclature");
  1. Встроенный вид — тот же компонент без заголовка и без панели параметров: параметры привязаны к форме (цех или номенклатура = текущий объект). Toolbar сокращён до «Обновить» и «Ещё»; строка состояния, отборы, виды и состояния — те же.
  2. Один запрос в двух формах различается вариантом, как у ListForm. Вариант объявляется вместе с запросом и задаёт свой стандартный вид — здесь скрыта колонка, которую задаёт карточка. Ключ видов — querylist.<ключ>.<вариант>, поэтому виды карточки цеха не попадают в карточку номенклатуры. Встраивания с одним вариантом делят виды, без варианта — общие виды ключа списка. Нужен ли вариант, решает разработчик: если колонки или стандартный вид в двух местах разные, вариант нужен. Стартовая проверка ловит необъявленный вариант. API в коде — эскиз, точные имена определит FQ-9.
