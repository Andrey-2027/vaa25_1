  1. Строка команд — отдельный toolbar под заголовком, как у списка и у ListForm. Команды UTR: «Сохранить», «Сохранить как…», «Обновить», «Ещё». «Видов» и команд над строками нет. В шапке остаются название, видимость («Только я») и признак «Не сохранено» — макет менялся после последнего сохранения.
  2. Две вкладки. «Результат» — ядро просмотра. «Запрос» — существующий редактор и конструктор, как на /queries.
  3. Панель параметров — ядро (UX-2). Значения по умолчанию берутся из документа. Введённые значения не сохраняются, поэтому период запрашивается при каждом запуске. Когда выполнять, решает правило режима (UX-3).
  4. Сетка служит редактором макета. Колонки и их заголовки, порядок, ширины, сортировка, отбор, группировка и итоги попадают в документ по «Сохранить» и применяются при открытии. Сохранённый отбор («Количество ≥ 100») зритель может снять. Ограничения данных автор задаёт в запросе и параметрах.

  1. Колонка-ссылка: значение подчёркнуто. По щелчку или из контекстного меню ячейки «Открыть <тип>» перечитывает объект с RLS и открывает его форму через E1. Форма работает по своим правам, других команд над строкой в UTR нет. Сортировки по ссылке нет (UX-7).
  2. Пункты «Сетка» — ядро, их диалоги ниже. Режим загрузки и свойства меняет только автор. Выгрузка появится в FQ-11. «Создать список по запросу…» видит только администратор: запрос и макет копируются в редактор «Списки по запросу» (FQ-6) без связи с отчётом.

  1. «Колонки…»: видимость, порядок перетаскиванием, заголовок и ширина. Рядом с заголовком видно поле запроса, из которого берётся колонка. «По запросу» возвращает заголовки и порядок из запроса. Ширину можно менять и прямо в сетке.
  2. «Итоги…»: функция подвала для каждой колонки. Для чисел — сумма, среднее, минимум, максимум; для любой колонки — количество строк; «нет» — без итога. Итоги считаются по всей отфильтрованной выборке (Д-Q5). FilterGrid это уже умеет (FooterAggregateKind).
  3. Группировка задаётся в самой панели: поле выбирают кнопкой или перетаскивают заголовок колонки, до трёх уровней. В узле — число строк и выбранный итог по числовой колонке. Уровни и итог узла на момент «Сохранить» становятся группировкой по умолчанию: отчёт открывается сразу сгруппированным. Для этого FilterGrid нужен публичный API чтения и установки состояния панели (FQ-3а).

Эти же диалоги — у списка по запросу. Администратор задаёт ими стандартный вид в редакторе «Списки по запросу» (FQ-6), сотрудник меняет сетку на время работы и сохраняет как вид.

select n.id as nomenclature, w.id as senderWorkshop,
       sum(i.quantity) as quantity, count(distinct d.id) as documents
from ReceivingDocumentItem i
  join i.document d
  join i.nomenclature n
  left join d.senderWorkshop w
where d.date between :periodFrom and :periodTo
  and (:workshop is null or d.receivingWorkshop.id = :workshop)
group by n.id, w.id

Отчёт требует исправления Запрос не прошёл проверку: поле «Склад» удалено из «Накладной».
  1. Документ хранит то, что нужно для повторного открытия. Результат конкретного запуска в документ не попадает.
  2. Конфликт ревизии: тот же отчёт сохранили в другом окне. Черновик остаётся на экране.
  3. Пропавшую колонку автор видит предупреждением и сохраняет исправленный документ. У зрителя колонка пропускается молча. Если запрос не проходит проверку, показывается «Отчёт требует исправления», подробности видит только автор.

Остальные состояния — «Не выполнялся», «Выполняется…», предел «Целиком в памяти» (30 000 строк), усечение «Первые N строк», «Нет доступа к данным», таймаут, квота — как в макете FQ-3: они принадлежат ядру.
