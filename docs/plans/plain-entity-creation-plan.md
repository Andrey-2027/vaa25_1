# Создание простой сущности PLAIN: отдельный генераторный срез

Все пять этапов завершены. Для [минимального контракта PLAIN](../architecture/plain-entity-creation-contract.md) доступны черновик `custom-plain-v2` в JSON v5, редактор и генерация Java, конфигурации форм и DDL. Сгенерированные файлы компилируются, схема всех скалярных типов сверена с Hibernate на H2 и PostgreSQL 17.

В [реестре сущностей](entity-registry-ux-plan.md) пункт «Простая сущность» открывает рецепт, выбранный по описателю. Повторный выбор активирует открытый черновик того же вида. Замена изменённого черновика другого вида требует подтверждения.

## Контракт

- Новый версионированный рецепт создания `kind = PLAIN` на обычном `BaseEntity`.
- Пользовательские реквизиты без автоматически навязанного состава справочника `code + name`.
- Согласованные модель/валидация, описание рецепта, JSON import/export, Java/формы, DDL и профиль применения/скачивания.
- Соблюдение действующей политики `FormSettings`, версий рецептов и ограничений поддерживаемых типов полей.
- Режим `EXISTING_ENTITY` остаётся режимом работы с существующим исходником, а не рецептом создания.

## Последовательность

1. Зафиксировать минимальный поддерживаемый состав сущности, представление, формы и профили записи — выполнено.
2. Добавить новый рецепт и описатель и проверить совместимость прежних JSON и рецептов — выполнено.
3. Подключить редактор черновика и генерацию к существующему диспетчеру — выполнено.
4. Проверить положительные и отрицательные сценарии, компиляцию сгенерированных файлов и соответствие DDL — выполнено.
5. Подключить доступность пункта меню через описатель поддерживаемого рецепта — выполнено.

## Готовность

Круг `PLAIN draft → JSON → validation → generated Java/forms/DDL → compilation` проходит целевые проверки. Остальные виды создания и их артефакты совместимы. Применение файлов и SQL остаётся отдельной командой с действующими допусками.
