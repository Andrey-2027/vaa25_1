# D-R S4: семантическая классификация production-типов артефакта platform-register-vaadin.
#
# Зачем реестр появился в том же срезе, что и модуль. Это тот же порядок, что у D3.5.0 и D-R S0:
# роль назначается тем изменением, которое создаёт артефакт, а не разбором задним числом.
# Разница с S0 здесь одна: типы не новые, они переехали — но переезд меняет носителя обещания
# (приложение -> артефакт), поэтому решения пересматриваются, а не наследуются. Забор —
# RegisterVaadinSurfaceRoleTest в самом модуле: его сборка (buildSteps манифеста) гоняет тесты,
# поэтому расхождение видно на сборке артефакта, а не только в сборке приложения.
#
# Формат: <role> <fqn>
# Роли (ровно одна на production-тип): APP_API | APP_SPI | MODULE_API | INTERNAL
#   APP_API    — поддерживаемый API приложения: приложение называет тип, платформа не наследует.
#   APP_SPI    — приложение реализует или расширяет тип; платформа вызывает обратно.
#   MODULE_API — контракт между platform-модулями.
#   INTERNAL   — реализация без compatibility promise: менять и удалять можно свободно.
# Вложенные типы наследуют роль владельца и отдельной записи не требуют.
#
# Замер, на котором стоят решения: `node scripts/analyze-register-closure.mjs --slice S4`
# (2026-10-14) — 5 файлов, 0 ссылок за границу среза, владельцы (pom модуля): platform-register,
# platform-vaadin, platform-core, platform-persistence, platform-identity-api, filtergrid-core.
# Прикладных имён в перенесённых классах нет ни одного: S1 убрал из адаптера прикладную сборку
# читателя (RegisterReaderFactory вместо EntityManagerFactory), поэтому разделение «общая часть /
# прикладная точка расширения» разрешилось само — общим оказалось всё, а точкой расширения
# остался механизм платформы (заменяемый бин + композиция FormTypeCustomization), и он проверяется
# забором RegisterVaadinExtensionPointTest: потребитель без своего бина получает стандартный
# адаптер, свой бин потребителя вытесняет его (по тождеству объекта), а без движка интерфейс
# падает, а не собирает себе второй читатель.
#
# Решения среза:
#
#   · RecorderRefPresentationResolver — APP_API по измеренному признаку: потребитель называет тип,
#     чтобы отрисовать колонку регистратора своей формой (в приложении это делают тесты, в
#     потребителе — его собственный адаптер форм). Тип читает канонически и пачками, поэтому
#     замена канонического пути остаётся за платформой, а вот имя типа — обещание;
#   · RecorderRefPresentation и RecorderRefDisplay — APP_API: первый — результат резолвера
#     (значение с подписью и ссылкой), второй — готовый компонент колонки, который потребитель
#     ставит в свой рендерер, не копируя ни показ недоступного документа, ни правило ссылки;
#   · RegisterFormCustomization — APP_SPI, и это решение, а не инерция старой роли: приложение
#     больше не объявляет его бином (S4), но платформа по-прежнему вызывает адаптер обратно
#     через FormResolver, а потребитель расширяет или заменяет его, когда стандартный интерфейс
#     ему не подходит. Обещание здесь двойное — поведение стандартных форм и возможность
#     отступления, — поэтому роль application-facing, а не INTERNAL;
#   · RegisterKeyDialog — INTERNAL: диалог смены ключа — реализация стандартного адаптера, и
#     приложение его не называет. Visibility (package-private) и роль сходятся: забор замыкания
#     API не даст вывести его в публичную сигнатуру случайно;
#   · RegisterVaadinConfiguration — INTERNAL по той же причине, что у срезовых конфигураций S1–S3:
#     имя авто-конфигурации не обещание, обещание — бины, которые она приносит (адаптер можно
#     заменить своим, @ConditionalOnMissingBean).
#
# Сверка с прикладным D1-реестром (platform-public-surface.txt) не даёт расхождений: прикладной
# main после S4 не называет ни одного типа этого модуля, поэтому новых записей там нет, а
# MODULE_API = 0 — измеренный факт: ни один другой платформенный модуль типов интерфейса не
# называет (platform-register-vaadin стоит в конце порядка выноса, следующий срез — не модуль,
# а сокращение обвязки S5).

# ---- APP_API (3)
APP_API org.ipro.vaadin.register.RecorderRefDisplay
APP_API org.ipro.vaadin.register.RecorderRefPresentation
APP_API org.ipro.vaadin.register.RecorderRefPresentationResolver

# ---- APP_SPI (1)
APP_SPI org.ipro.vaadin.register.RegisterFormCustomization

# ---- MODULE_API (0)

# ---- INTERNAL (2)
INTERNAL org.ipro.vaadin.register.RegisterKeyDialog
INTERNAL org.ipro.vaadin.register.config.RegisterVaadinConfiguration
