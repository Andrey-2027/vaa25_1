# D3.5.7: reviewed-реестр шва Report → Form.
#
# Предмет: report-слой называет типы UI-платформы. Направление обязано быть односторонним и
# узким — это предпосылка среза D3.7 (report переезжает в свой артефакт как ПОТРЕБИТЕЛЬ
# platform-vaadin, а не наоборот).
#
# Односторонность физически держит VaadinModuleCompositionTest: platform-vaadin не знает ни
# report, ни DR/JR. Здесь проверяется другая половина контракта, которую не держит
# никто: report имеет право называть ТОЛЬКО опубликованные роли, и объявленный набор
# держателей шва — это то, что переезжает вместе со слоем.
#
# Источник роли — platform-vaadin-surface.txt (единственное место, где роль записана).
# Здесь роль не повторяется намеренно: два записанных решения об одном типе расходятся, а
# сверка «тип шва обязан иметь APP_API/APP_SPI» — настоящая проверка, а не пересказ.
#
# Измерение идёт по ИСХОДНИКАМ слоя, а не по байткоду. Причина измерена, а не предположена:
# org.ipro.form.SelectionForm попадает в шов только через каст
# ((SelectionForm) assembler.assemble(...) в ReportParamForm), а проверка байткод-зависимостей
# (ArchUnit getDirectDependenciesFromSelf) такой зависимости не видит — шов оказался бы
# на тип уже. Комментарии и строковые литералы из текста снимаются, иначе упоминание типа
# в javadoc считалось бы употреблением: ровно эта нестрогость чинится в D1 тем же шагом.
#
# Формат строк:
#   layer <корень исходников слоя: каталог или файл>       — где искать слой (переезд правит эту строку)
#   seam  <fqn платформенного типа> <fqn держателя> ...    — измеренный шов с держателями
#   only  <fqn типа> <почему у типа нет потребителей вне шва>
#
# Держатели записаны FQN, а не путями файлов: D3.5.4 сохранил FQN при переносе, поэтому при
# переезде слоя меняются только строки `layer`, и реестр не приходится переписывать целиком.

# --- что обязан забрать с собой переезд слоя (D3.7; временно отложен до появления ресурса) ---
# Подготовка к срезу, снятая в D3.5.7, а не предположение:
#
# 1. Регистрация. Файл AutoConfiguration.imports приложения содержит сейчас пять строк с
#    report-owned конфигурациями в пакетах org.ipro: ReportCatalogAutoConfiguration,
#    ReportStudioAutoConfiguration, ReportStudioPersistenceAutoConfiguration,
#    JrPersistenceAutoConfiguration, JrAutoConfiguration. У слоя
#    есть и своя persistence-конфигурация (@EntityScan/@EnableJpaRepositories), то есть переезд
#    меняет не только объявление бинов, но и область сканирования сущностей — а это не падает при
#    старте, а меняет поведение. Прецедент рядом: в D3.5.4 Vaadin-адаптер телеметрии держался
#    только на component scan пакета org.ip и исчез бы молча, поэтому там появился
#    PlatformVaadinWiringIT, проверяющий живой контекст. Вывод для D3.7: переезд регистрации
#    обязан проверяться бином в живом контексте, а не фактом наличия imports-файла.
# 2. Замыкание. PlatformSubsystemClosureTest держит запись org.ipro.reportstudio -> пусто (D3.5.4)
#    именно как предпосылку этого среза: когда пакет уедет в артефакт, запись снимается решением,
#    а не потому что «тест покраснел».
# 3. Заборы, читающие пути. D1-заборы читают src/main/java/org/ip, поэтому переезд обязан сдвинуть
#    их APPLICATION_PACKAGE — иначе они станут вакуумными и останутся зелёными. Здесь пути не
#    проблема: сдвигаются только строки `layer` выше, а измерения шва записаны FQN.
