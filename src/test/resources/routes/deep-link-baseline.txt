# E2.0 baseline публичных адресов глубокой ссылки (ADR-0009 §3–§5).
#
# Этот файл — версионируемая часть контракта E2, а не отчёт. Числа и имена здесь означают
# обещание: опубликованный адрес не меняется без legacy-записи, а новый публичный адрес
# появляется только вместе с записью в этом файле и проходящим `DeepLinkRouteBaselineTest`.
#
# Формат записи — поля `<key>=<value>` через пробел, порядок полей фиксирован.
#
# alias=<key>  внешний ключ маршрута: ASCII lower-kebab-case, выводится из имени класса
#              один раз (§4). Ключ выведен, а не выбран: ручной ключ потребовал бы
#              декларации на каждый тип.
# class=<fqn>  persistence-класс. Источник истины публикации — ManagedEntityCatalog
#              (@EntityMetadata и не @TableSectionMetadata), а не этот файл: файл лишь
#              фиксирует результат и не может ввести тип, которого нет в каталоге.
# item=<...>   разрешённые ITEM-variant ключи (ключи FormRegistry) через запятую;
#              `default` — default-ветка (кастомная или generic), которая существует всегда.
# list=<...>   то же для LIST-variant ключей.
# context=<.>  обязательные контекст-фильтры СПИСКА этой сущности (ContextFilterField
#              .requiredAuto/requiredLookup/requiredSelect) через запятую; `-` — нет.
#              Непустое значение читается буквально: список этого типа не linkable до
#              объявленного RouteContextCodec (ADR-0009 §5), сколько бы вариант ни был
#              зарегистрирован. Item-маршрут поле не затрагивает: существующая запись
#              открывается без контекста создания.
# legacy=<.>   прежние ключи того же типа через запятую; `-` — переименований не было.
#              Удаление legacy-ключа (при сохранении типа в каталоге) — сломанная ссылка,
#              а не уборка.
#

# ---- static routes (ADR-0009 §3)
# Существующие адреса приложения и их владельцы: ровно один класс объявляет @Route/@RouteAlias
# на путь. `/` — корневой @Route у MainLayout (корень остаётся home, а не host ссылки).
#
# С E2.3 host ссылки здесь: `@RouteAlias`-шаблоны на том же MainLayout. Шаблон — не сущность,
# а форма адреса: какие типы под неё подходят, решает каталог адресов, а не таблица маршрутов.
# E3.0 добавил третий шаблон — `/entity-explorer/:entityKey`: адрес типа (без id записи),
# его отдельный обработчик и проверка роли живут в host'е (ADR-0010).

route /entity-explorer/:entityKey org.ip.views.MainLayout
